## 用户反馈与事实

用户在另一台电脑点击“导出规则包”时，提示平面的方位具有动态必填要求，当前样包只支持静态 required。用户已确认触发按钮为导出，而非生成路线。

根因调用链：GenerateView.exportRulePackage → downloadValidatedRulePackage → sampleRulePackageFiles → sampleRulePackageTables → factor。PM-063引入的共享特征在present=true时要求其direction/it/ra必填；PM-035样包适配器明确拒绝这种约束。本地接收端config_route_engine.py的required仅接受bool，不能直接等价表示。错误又写入GenerateView通用error，误用“规则验证或路线生成未完成”标题及“返回规则定稿”操作。

## 当前确认设计

保留三数组及稳定短编号；因素增加可选required_when条件，当前仅输出present=true的同特征条件。共享参数必填由该条件决定，未选时不强制，与原生验证一致。短编号重写同步重写条件引用；导出侧TS/Python协议校验与接收端均校验引用和类型，不允许依赖路线结果或CAD数组行上下文。读取器先完成因素取值，再校验条件必填，避免依赖因素顺序；参数预览仍允许未填。旧包没有新字段时沿用静态required行为。

接收端基于用户本机KmAI读取器当前文件做最小补丁；在本仓库integrations/kmai保存可交付的读取器及说明供其它电脑升级和持续回归，不更换整个KmAI项目。原生规则、数据、模型设置不修改。不自动提交Git或发布。
