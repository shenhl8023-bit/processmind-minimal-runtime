- 本机正式API日志对应项目10：`POST /api/projects/10/analysis-guidance/generate`返回503，耗时90.31秒，代码`analysis_model_response_invalid`。不是此前PM-091的导出失败。
- `analysis_guidance_generation.py`把LLMResponseError映射到以上代码；`llm_client.py`在成功响应中无法提取非空正文时抛出该异常。它不等于HTTP接口连接失败，也不能单凭此认定协议不兼容。
- `llm_errors.py`把KeyError/TypeError/ValueError统称为响应格式无效，当前提示缺少具体原因。LLMResponseError属于ValueError。
- 离线调用当前提取函数，空choices、空content和仅有reasoning_content均产生同一LLMResponseError及llm_response_invalid；这证明提示无法区分这些情况，不证明本次响应属于其中某一种。
- 第一条提示来自`useAnalysisReviewPersistence.ts`：用户确认工序时，规则草稿为null，前端必答检查阻止提交。第二条来自问答生成请求；界面汇总两条通知，不是两个模型失败记录，不能未经复现将两者必然因果绑定。
- 只读检查时，项目10未保存analysis_guidance_json，param_audit_answers为0；这仅说明没有本次完整问答配置落库，不证明历史数据丢失。失败路径不覆盖已有配置。
