# 部署功能可见性配置（PM-060）

部署管理员可在部署根目录（`product-profile.json` 所在的应用目录）创建可选的 `product-features.json`。示例位于 `docs/配置模板/product-features.example.json`。这不是项目、用户或模型设置，适用于整套部署。

```json
{
  "template_mapping_enabled": false
}
```

`true` 显示第六步，`false` 隐藏其导航、入口和旧映射页面路由。默认文件不存在或内容为 `{}` 时保持可见。仅接受 JSON 布尔值，不接受字符串或数字；文件格式错误、字段拼写错误、读取失败会在启动时报告功能配置错误。

配置随产品配置在服务启动时读取并缓存。修改后重启应用服务，再刷新浏览器；本功能不提供运行中热更新。重新设为 `true` 后，第六步仍使用内部编号 6，并继续读取原有映射，不需要重新导入。配置读取不执行数据库更新、删除或迁移。

若需要其他位置，可由启动环境设置 `PROCESSMIND_FEATURES_PATH`。支持绝对路径；相对路径以部署根目录为基准。显式指定的文件必须存在。未设置该变量时始终读取应用根目录的 `product-features.json`，不跟随 `PROCESSMIND_PROFILE_PATH` 或用户数据目录移动。支持 UTF-8 和 UTF-8 BOM。

此开关只控制可见性，后端仍保留完整版的模板 API、映射数据及导出兼容能力；既有第二步模板别名和第四步三表发布链仍按版本能力处理。隐藏开关不能替代访问控制。不要为隐藏第六步修改 `product-profile.json` 的版本、能力字段或到期时间。基础试用版仍受原版本能力与到期限制，设为 `true` 不能解锁映射功能；完整版不会因隐藏而增加试用限制。

前端启动时读取 `/api/product-status` 的有效 `template_mapping_enabled`（版本能力与可见性开关的交集）。完整版只读取功能状态，不启动试用轮询、到期计时或状态失败锁屏；接口不可用时保留当前状态，新页面默认可见。导航与旧路由使用可见性状态，数据保存及发布链使用版本能力。

完整包和基础包共用本配置规则。打包脚本随包提供示例及本说明；如果源码根目录已放置 `product-features.json`，staging 会一并复制它。没有配置文件的交付仍默认可见（基础版依旧无映射能力）。也可以在解压后、启动前按示例创建文件；不需要重建前端，不修改正式模型配置或项目数据。
