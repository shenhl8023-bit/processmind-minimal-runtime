# ProcessMind 数据库迁移与维护

本文适用于当前 SQLite 运行方式。API 启动时会自动执行尚未应用的版本化迁移；重复工序审计和修复必须通过显式维护命令执行。

## 1. 自动迁移

迁移运行器位于 `process-plan-agent-api/app/services/db_schema_migrations.py`，按以下顺序执行：

| 版本 | 名称 |
| --- | --- |
| 1 | `legacy_project_schema_v1` |
| 2 | `workflow_review_schema_v1` |
| 3 | `route_review_indexes_v1` |
| 4 | `rule_package_lifecycle_v2` |
| 5 | `retire_kmai_factor_mappings_v1` |

成功迁移写入 `schema_migrations` 的版本、名称、时间和 JSON 结果。迁移失败会回滚当前启动事务，并在 API 日志中报告失败版本和名称。不要手工修改 `schema_migrations`。

## 2. 停止服务

执行审计或写入修复前，先停止 API，避免维护期间产生并发业务写入。

Windows PowerShell：

```powershell
Set-Location D:\Project\processmind-minimal-runtime
\.\stop-windows.cmd
```

POSIX shell：

```bash
cd /path/to/processmind-minimal-runtime
./stop-windows.cmd
```

如果使用其他启动方式，确认 `uvicorn app.main:app` 已停止后再继续。

## 3. 只读审计

默认数据库路径为 `data/db/process_mind.db`。也可以通过 `--db` 指定绝对路径。

```powershell
\.runtime\python\python.exe scripts\maintain_database.py --db data\db\process_mind.db audit
```

```bash
python scripts/maintain_database.py --db data/db/process_mind.db audit
```

审计输出包括：已应用迁移、待应用迁移、重复工序组和工序身份索引状态。该命令不创建迁移、不更新审计表、不写业务数据。

## 4. 修复预览

先运行预览，确认每组保留的工序 ID、删除的工序 ID 和重挂的因素 ID：

```powershell
\.runtime\python\python.exe scripts\maintain_database.py `
  --db data\db\process_mind.db repair-operation-duplicates
```

预览不会创建备份，也不会修改数据库。

## 5. 应用重复工序修复

确认预览结果后执行：

```powershell
\.runtime\python\python.exe scripts\maintain_database.py `
  --db data\db\process_mind.db repair-operation-duplicates --apply
```

命令会：

1. 使用 SQLite 在线 `backup()` API 在同目录创建 `process_mind.db.bak-YYYYMMDDTHHMMSSZ`。
2. 在 `BEGIN IMMEDIATE` 事务中重新扫描重复组。
3. 将重复工序因素重挂到保留工序，只删除完全重复因素。
4. 删除重复工序，验证无重复组和悬空因素。
5. 删除普通工序身份索引并创建唯一索引。

成功输出中的 `Backup:` 路径必须保留。命令不会覆盖已有同名备份，也不会自动删除原数据库。

## 6. 失败恢复

如果 `--apply` 返回非零：

1. 保持 API 停止，保留当前失败数据库，不要继续写入。
2. 确认错误输出中的 `Backup preserved:` 路径存在且可以打开。
3. 将当前数据库改名保存，例如：

```powershell
Move-Item -LiteralPath 'D:\Project\processmind-minimal-runtime\data\db\process_mind.db' `
  -Destination 'D:\Project\processmind-minimal-runtime\data\db\process_mind.db.failed'
```

4. 用备份恢复原文件：

```powershell
Copy-Item -LiteralPath 'D:\Project\processmind-minimal-runtime\data\db\process_mind.db.bak-YYYYMMDDTHHMMSSZ' `
  -Destination 'D:\Project\processmind-minimal-runtime\data\db\process_mind.db'
```

5. 先重新执行只读审计，再启动 API。

恢复时不要删除 `.failed` 文件，直到 API 健康检查和业务抽查完成。

## 7. 重启检查

启动 API 后检查健康接口：

```powershell
Invoke-WebRequest http://127.0.0.1:8000/api/health
```

再停服执行一次 `audit`，确认迁移均已应用、重复工序数量为零或仍有明确的人工处理计划。

## 8. 支持边界

- 当前迁移语句和维护命令只支持 SQLite。
- 不要把迁移命令用于 PostgreSQL 或其他数据库；多数据库支持属于 R-008。
- 不要直接复制正在写入的 SQLite 主文件作为备份；使用维护命令生成的在线备份。
- 不要在启动脚本中加入重复工序自动合并逻辑。
