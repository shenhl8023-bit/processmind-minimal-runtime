# ProcessMind 系统简介

ProcessMind 是一个面向机械加工场景的“典型工艺规程智能体”。它把多份历史工艺规程中的工序、工步和样本证据整理成可审核的标准路线，再把审核后的判断沉淀为规则包，用于验证和生成新的工艺路线。

系统适合三类使用者：工艺工程师用它整理历史路线和分析工序适用条件，规则审核人员用它核对证据并发布规则，部署或维护人员负责启动服务、配置模型和管理运行数据。

## 核心工作流

系统顶部的六步导航对应一个项目内的完整工作流：

1. **上传资料**：新建或选择任务，上传典型工艺规程文件。主资料支持 PDF、Word、Excel 和 JSON；后端保留参考资料能力，但当前最小运行包默认隐藏参考资料卡片，具体以交付版本页面为准。
2. **路线归并**：系统从多份规程中抽取工艺路线全集，生成归并候选。用户确认、拒绝或改名候选，并在需要时调整标准路线的顺序、合并、拆分和删除，最后保存标准化母路线。
3. **规则分析**：系统按已保存路线逐段展示样本覆盖、原始工序明细、内容证据和文档来源。用户通过问题树确认材料、结构、精度、要求等影响工序是否出现的因素，也可以打开原文件核对上下文。
4. **模板映射**：导入 Kmsoft XML 分组模板，把需要按零件特征判断的工步关联到模板分组或特征；系统提供校验和智能推荐，用户可以人工调整映射。
5. **规则定稿**：逐条审核规则，通过统一“规则修改”入口选择始终出现、人工选择或条件判断。字段条件支持“全部满足／满足其一”，可组合当前任务中任意工序的触发、先后、依赖和互斥关系；保存并确认后，完成预检并发布当前规则包。
6. **验证生成**：加载已发布规则包，填写零件条件，系统按规则输出工序顺序与工序工步树。结果可以展开查看、复制 JSON 或导出 JSON 文件。

## 两个辅助入口

- **工艺知识库**：从当前内置的轴套类工艺说明、历史工艺和加工能力样例中检索答案。回答会附带可追溯的原始记录或来源定位；典型路线、历史执行记录和加工能力是不同类型的参考，不应混为一谈。
- **模型设置**：配置模型服务的 API 地址、API Key 和模型名称，并使用“测试连接”检查调用是否可用。没有可用模型时，部分本地抽取和知识检索仍可查看已保存的本地记录，但依赖模型的识别、推荐或回答可能无法完成。

## 主要产物

- 项目资料及其解析结果。
- 可保存、可回看的标准化母路线。
- 每道工序的因素判断、问题树答案和样本证据。
- 已确认的模板分组映射。
- 带版本的已发布规则包。
- 与发布版本冻结一致的三个下游配置文件：`factor_table.json`、`full_route_table.json`、`rule_table.json`。
- 基于规则包和零件条件生成的工序工步树及 JSON 结果。

## 使用边界

规则编辑适用于当前任务中的任意工序、字段和关联关系，镀铜／除铜只是操作示例。第六步根据因素输入推演路线；下游 CAD 引擎再结合实际零件几何筛选映射工步。无法无损转换为三表的规则会在发布预检时阻断，具体原因及处理方式见使用说明。

ProcessMind 的 AI 能力用于抽取、推荐、归纳和生成候选，系统不会替代工艺人员对图样、标准、设备能力、质量要求和现场约束的最终判断。路线归并、问题树答案、模板映射和规则发布都应由熟悉业务的人员审核；只有发布后的规则包才用于正式的路线生成。

系统按项目保存状态。删除任务会同时删除其文档和提炼结果，且无法恢复；运行数据、上传文件和数据库应按部署环境纳入备份范围。详细启动、操作步骤和故障处理请参阅[《ProcessMind 用户使用说明》](./用户使用说明.md)。
