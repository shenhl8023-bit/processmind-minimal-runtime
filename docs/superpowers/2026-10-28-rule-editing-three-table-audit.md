# 规则修改与三文件生成审查记录

日期：2026-10-28。范围：规则编辑、确认、编译、发布预检、冻结快照、ZIP 导出，以及三表与原生规划的一致性。按 Superpowers 的代码审查、系统排错、测试先行与完成前验证流程执行。

三个交付文件：`factor_table.json`、`full_route_table.json`、`rule_table.json`。

## 已修复的可复现问题

### 规则编辑

- 历史排除规则或跨工序动作从“设置工序关联”入口进入时，会被转换成仅纳入当前工序的配置。现保留原编辑器及完整动作。
- 历史多目标关联进入单工序配置编辑器会丢失目标。现保留历史多目标关联格式。
- 编辑期间后台刷新后，取消草稿再重开仍使用旧候选，可能覆盖新规则。现取消时重新同步最新服务端 review。
- 历史关联缺省 `source_match` 时，摘要误显示“全部出现”，与实际默认任一匹配不同。摘要统一为任一匹配。

### 条件与因素编译

- 前后端历史 Bool 要求转换忽略 `op/value`，把 `eq false` 或 `neq true` 也当成正向要求。现保留四种 eq/neq 极性及外层 not；无法等价转换的 presence 条件保留原样交由校验处理。
- 普通已确认条件的完整选项集被裁剪，可能丢掉用户确认的非命中选项。所有已确认字段定义均作为审计依据保留。
- 负向多选条件的自动测试会生成 `__other` 非法选项；同字段正反组合还可能相互覆盖，造成合法规则无法预检。现使用合法选项，并按整组集合约束生成测试输入，覆盖 contains、contains_any、contains_all 与子句正反顺序。

### 三文件与规划结果

- 可选前置工序缺席时，原生对子集重新排序，与三表固定母路线顺序不同。现先取得完整母路线拓扑顺序，再筛选实际纳入的工序；选择集合保持原语义。
- 三表用因素字典的 `required` 代替输入 schema 必填性，可能误触发或漏校验。现必填性以实际输入 schema 为准。
- 必填 Bool 缺失时，下游隐式当 false。三表必填标量 Bool 显式设置 `default:null`，缺失报错，用户明确填写 false 仍有效。
- 校验器只检查单工序内部工步 ID，漏掉跨工序重复及工步/工序 ID 碰撞。现对公共节点命名空间统一查重。

### 发布与下载

- 普通已确认条件未审计字段标签、选项、因素字典。现与统一工序配置采用相同的服务端确认定义核对。
- 预检忽略工作流版本，过期页面仍可能显示可以发布。现返回 409 及当前 revision。
- 冻结三表仅核对自身 hash，可能与其他项目、路线或原生规则包混用。新快照绑定规则包内容 hash，并验证来源与包身份。
- 旧快照缺新绑定时，用它自身冻结路线和原生规则重编译比对，保持合法历史包兼容，不使用实时映射拼接。
- 前端接受草稿或项目、路线、内容不一致的响应。现拒绝错误响应及其下载/成功回调。
- 发布期间切换项目再切回会绕过旧响应检查；其他项目也可能收到过期映射错误。现用同步失效标记和请求上下文隔离。
- ZIP 下载异常会提前报告导出成功，并误报服务断连。现下载步骤单独报告错误，完成触发下载后才调用导出回调；下载文件名同时清理控制字符。
