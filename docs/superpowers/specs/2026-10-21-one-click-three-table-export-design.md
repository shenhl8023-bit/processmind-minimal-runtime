# 一键导出三表规则包方案

日期：2026-10-21。状态：待用户审阅。

## 目标

用户完成工艺路线确认、模板分组映射和规则定稿后，点击“导出规则包”即可得到三个符合既有协议的文件：`factor_table.json`、`full_route_table.json`、`rule_table.json`。用户无需手工制作 JSON，也不需要在导出时选择字段或编辑文件。

本方案中的“一键”描述用户操作，不表示模型在点击时自由生成三个 JSON。系统使用已经保存的路线、映射和规则定稿作为输入，由确定性编译器生成文件；模型可在前置的规则提取阶段提供草稿或建议，最终采用的规则必须已经过定稿。

## 当前基础

工作区已有模板映射步骤、规则定稿、三表编译器、协议校验、发布快照和 ZIP 下载流程。交付记录显示三表格式及实际下游路线引擎专项测试已覆盖。当前方案主要明确用户可见的一键导出契约及端到端验收，而不是重新实现这些模块。

需要继续通过真实用户流程验收的重点是：入口是否清晰；预检失败时能否准确带用户回到待处理项；当前项目中待确认规则是否能够被发现并阻止正式导出。三表格式正确不等同于业务规则已经正确确认。

## 用户流程

1. 用户在前置步骤确认最终工艺路线，完成模板分组/工步映射，并定稿因素与规则。
2. 用户点击“导出规则包”。
3. 系统读取同一工作流版本中的最终路线、有效映射和规则定稿，构造发布快照。
4. 系统先做预检。若预检通过，确定性编译并校验三张表，保存冻结快照，再打包下载固定名称的三个 JSON 文件。
5. 若预检或编译失败，系统不下载部分文件，而是展示可定位的问题，例如待确认规则、无效映射、缺失必需因素、重复/未知 ID，或无法等价表达的规则条件。用户可跳转到对应步骤修正后重新导出。

导出后的结果绑定到该次发布快照。后续编辑路线、映射或规则不会悄悄改变已下载版本；用户再次导出时生成新的快照。

## 三张表的编译来源

- `full_route_table.json`：以用户确认的最终工艺路线及顺序为准，使用有效模板映射构造工序/工步候选。保留稳定 ID 和重复名称节点的独立身份；辅助工序允许 `steps: []`。不输出运行时字段，如 `technical_requirements` 或 `is_last`。
- `factor_table.json`：来自定稿因素及因素绑定定义。每个因素按协议输出 key、label、type、source、visible，以及适用的 options、required、default。取值路径必须对应真实 CAD 输入或人工覆盖字段，不把来源说明伪装成数据路径。
- `rule_table.json`：来自已定稿的启用条件，target 引用全集路线中的稳定 process_id 或 step_id。规则条件只使用目标协议支持的表达式；只有语义等价时才允许转换。

三表分别使用既定文件名、顶层数组、字段类型和引用协议。审计证据、提取来源、审核状态、编译器版本和哈希保存在系统内部快照中，不混入这三个外部文件。

### 工序精度字段

`full_route_table.json` 中的 `precision` 表示工序阶段标签，例如“粗加工”“半精加工”“精加工”；它不是 CAD 特征的 `feat_rank`，也不由候选特征的精度等级计算。

全集路线表在模板分组映射阶段随最终路线一起构造。最终工艺树中已有且已确认的工序精度直接沿用；辅助工序没有加工阶段时使用“辅助工序”。加工工序缺少精度或精度未确认时，映射/发布预检应指出具体工序并要求补充确认，不依据“精车”“精密”等工序名关键词猜测，也不以 CAD 特征等级推断。精度未补齐前不得发布或导出三表。

因此，模板映射负责确认工步到模板分组/特征的候选关系，同时承接最终工艺树的工序阶段信息；它不改变或重算该阶段。导出的 `full_route_table.json` 保留已确认的精度值，作为规则定稿和规则包导出的同一来源。

## 预检与错误处理

预检至少覆盖：路线及映射已保存且版本匹配；需处理的映射已确认；加工工序的 precision 已确认且非空；辅助工序 precision 为“辅助工序”；因素字段和 source 合法；所有 process_id/step_id 全局唯一；规则 target 和因素引用存在；target 不重复；条件结构、类型与依赖合法；规则可被目标协议等价表达；数组顺序保留最终确认顺序。

对于缺少证据、规则冲突或目标协议无法表达的情况，系统应指出对象、原因和建议处理步骤，不静默猜测、丢弃或降级规则。预检失败不创建新的正式发布快照，不生成不完整 ZIP。错误信息应保留足够上下文，以便用户从导出入口跳转到路线、映射或规则定稿位置。

## 一致性与可追溯

三张表必须在一次发布事务中从同一组路线版本、映射修订和规则修订编译。保存文件内容及来源版本/哈希；下载只读取该冻结快照，不能把已发布规则与实时未发布映射临时拼接。若编译或保存失败，不留下只包含部分文件的发布包。

提取的因素与规则在内部保留资料来源和审核状态。已确认内容进入编译；待确认内容通过预检阻止正式导出。模型建议本身不直接成为正式配置。

## 验收标准

1. 从用户界面点击一次“导出规则包”，成功后 ZIP 恰含三个固定名称的 JSON 文件。
2. 文件符合既有协议：顶层数组、字段名/类型正确、UTF-8 中文直写，不含额外包装、内部审计字段或运行时字段。
3. 三表来自同一个冻结版本；修改源数据不改变既有发布版本，再次导出才生成新版本。
4. 所有 ID 唯一且引用有效；全集顺序与确认后的最终路线一致；候选仅来自有效映射；加工工序 precision 沿用已确认的最终路线阶段，缺失值会阻止导出，不从工序名或 CAD 特征精度猜测。
5. 有待确认规则、无效映射或不可等价转换的规则时，系统阻止正式导出并提供具体定位信息，不返回部分 ZIP。
6. 导出的三表可由目标路线引擎加载；使用代表性 CAD 输入运行后，结果与预期路线在工序顺序、候选过滤和规则启用行为上相符。
7. 再次导出相同且未修改的已定稿数据，生成内容稳定一致。

## 范围边界

本方案覆盖三表配置的提取结果定稿、编译、预检、冻结和下载体验。不把技术要求生成纳入三张表；技术要求仍由既有专用流程处理。方案也不要求模型在导出点击时再次自由推理，避免导出结果随临时模型响应变化。
