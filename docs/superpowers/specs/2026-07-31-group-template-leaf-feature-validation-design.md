# 分组模板叶子特征校验设计

## 目标

模板是否标准不能只根据 XML 结构完整性判断，还必须检查可落地映射的子分组是否配置了合法“特征选择”。结构父分组可以为空，但每个叶子分组必须至少匹配一个系统特征字典中的特征。

## 判定规则

- 有子节点的父分组是结构容器，可以不配置“特征选择”。
- 没有子节点的叶子分组必须至少配置一个非空“特征选择”。
- 每个非空特征仍必须存在于系统内置 `FeatureTemplate.xml`。
- 叶子分组缺少特征时产生阻断问题 `missing_leaf_feature_selection`，问题中保留完整分组路径。
- 存在空特征叶子、非法特征或其他既有阻断问题时，`can_confirm=false`。
- 至少存在一个分组和一个合法特征的要求由叶子规则自然保证，无需增加重复的全局错误。

样例预期：

- `临时壳体4.xml`：通过，9 个叶子分组均有合法特征。
- `套筒类.xml` 和 `套筒类(未指定参数).xml`：通过，空特征节点均为结构父分组，15 个叶子分组均有合法特征。
- `新衬套模板.xml`：不通过，存在空特征叶子分组。
- `飞机壁板类1.xml`：不通过，所有叶子分组均缺少特征。

## 后端

在 `group_template_xml.py` 的递归解析中，先解析当前分组及其子节点，再根据最终 `children` 判断当前节点是否为叶子。叶子且 `feature_values` 为空时追加：

```text
code: missing_leaf_feature_selection
message: 叶子分组必须至少配置一个特征选择。
path: 当前分组完整路径
value: 空字符串
```

预览接口继续返回统一的 `validation_issues` 和 `can_confirm`。确认/替换接口仍会重新解析同一文件，因此无法通过绕过前端保存不标准模板。

已有正式模板不做后台批量重校验或自动删除。新规则只在用户首次确认、主动更换或重新上传 XML 时执行，避免现有项目在无操作情况下失效。

## 前端

预览页沿用现有问题列表：

- 有 `missing_leaf_feature_selection` 时显示中文说明“叶子分组缺少特征选择”。
- 显示对应完整分组路径。
- 页面摘要显示“模板不标准”，确认按钮保持禁用。

映射工作台区分结构节点和可映射节点：

- `feature_selections.length > 0` 的节点可以成为手工和智能映射目标。
- 无特征父分组仍可展开、收起并查看子树，但不能被选为映射目标。
- 无特征节点使用禁用样式和说明“结构分组，不可映射”。
- 智能候选生成和后端候选构建都只使用有特征的节点，避免前后端结果不一致。
- 保存映射接口除校验路径存在外，还必须校验目标分组具有非空合法特征，禁止绕过前端创建无特征映射。
- 旧模板中的既有无特征正式映射仍可展示并标记为“需要重新映射”；用户必须移除或改映到有特征分组后才能再次保存。

## 数据与兼容性

不新增数据库字段，不改变模板或规则包结构。`validation_issues` 已支持 `code`、`message`、`path` 和 `value`，可直接表达新问题。

模板修订号、内容哈希、替换影响分析和旧映射迁移逻辑保持不变。新校验失败时只阻止新模板确认，不修改项目当前模板与映射。

## 测试

后端解析测试：

- 空特征父分组且所有叶子有合法特征时通过。
- 单个空特征叶子产生 `missing_leaf_feature_selection`，路径准确，并阻止确认。
- 叶子同时具有合法和非法特征时沿用非法特征错误。
- 混合树会逐条报告所有空特征叶子。
- 五个真实样例符合上面的预期结果。

后端映射测试：

- 程序候选不会包含无特征父分组或空特征节点。
- 大模型仍只能从合法候选中选择。
- 保存映射接口拒绝指向无特征节点的映射，并返回可定位的错误。

前端测试：

- 无特征结构节点不可作为映射目标。
- 有特征节点仍可手工映射。
- 既有无特征映射会显示待修正状态，并阻止保存，直到用户移除或重新映射。
- 预览问题详情能显示空特征叶子的完整路径。
- 现有自动解析、重新选择、取消替换和焦点刷新回归继续通过。

浏览器验证：

- 上传标准模板时可确认并进入映射。
- 上传不标准模板时显示具体空特征叶子，确认按钮禁用。
- 已确认模板和正式映射在失败预览或取消替换后保持不变。
