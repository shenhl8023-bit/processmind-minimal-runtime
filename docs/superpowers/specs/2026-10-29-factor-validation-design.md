# 三表输入约束对齐

用户在已明确“两端支持范围校验、仍保留三份文件”的方案后要求直接修复，无需再次审批。目标是当前三个 IT 因素保留 5～10 范围且正常预检/发布，KMAI 在实际生成时拒绝越界输入。

方案采用因素对象的可选 `validation`，支持数值 `min/max`、字符串/枚举/多选 `min_length/max_length`，边界包含自身；不增加文件，不删除工程限制。另一方案是取消约束或仅关闭拦截，会继续接受错误值，无法满足要求。沿用 Python 标准库及 Python 3.8 兼容性。

编译器升级 `/5`；历史 `/1`～`/4` 按原语义重建冻结内容。新因素约束必须为合法有限数字或非负整数，类型匹配且范围顺序正确；只有存在的非空有效值才应用范围，必填检查仍独立执行。新编译仅输出生效约束；经 CAD 重复来源转换后无法等价表达的集合/文本长度约束继续明确拒绝，不猜测其含义。

KMAI 在配置加载时验证约束形状，在路线生成及所有人工覆盖/CAD来源取值后校验有效值；参数预填允许显示越界值，以便用户修改，生成必须拒绝。UI 为数值显示范围并设置 min/max，允许小数的 number 使用 step=any。API/引擎是权威校验，不能靠前端绕过。
