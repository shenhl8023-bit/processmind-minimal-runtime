# 有效映射加工节点的三表发布设计

用户已在当前会话确认本方案并授权直接实施。三表字段保持兼容 KMAI v2；内部路线、映射记录、工序/工步 ID 不迁移。

## 发布语义

- 完整映射路线先经过现有目录、身份、顺序和规则编译校验。
- 交付的加工工序仅包含具有非空有效 candidates 的工步；工步全部被剔除的加工工序不交付。辅助工序保留原语义。
- 有效映射是交付准入，实际零件仍须命中特征。交付加工工序不使用 required=true 绕过 KMAI 的空工步剔除。
- 被剔除节点的规则移除；selected_processes 对被剔除工序的引用按 false 进行布尔化简，不能直接删去条件。必要前置关系不能被悄悄解除；不可满足的必要前置需返回明确预检错误。
- requires 沿用现有规划器的全部前置语义，不受 source_match 影响；触发关系继续保留 any/all 的区别。永久为 false 的工序沿无环依赖传播，not(false) 正确保留为 true。
- 仅移除因交付筛选而不再使用、且原来被规则使用的因素；无条件公共输入仍保留。
- 剔除后完全没有可交付工序，或剩余工序均永久无法触发时，预检明确提示补充映射或修正规则，不发布没有执行内容的空包。
- 严格的通孔/盲孔含义不自动合并。现有 source 人工补参能力继续使用，不推断不存在的 feat_rank 或孔型。

## 结构和兼容

新建独立发布投影模块，消费已编译三表和原规则包，产出交付三表与导出说明。现有编译器保留完整编译语义，以便历史快照重现。

发布编译版本升级为 demo-three-table/3，冻结原映射路线、来源哈希、交付路线哈希和投影说明；读取时通过冻结原包和原映射路线重编译验证。版本 1/2 仍执行其原校验路径，不能用今天的映射重建历史包。使用已有 JSON 存储字段，无数据库结构迁移。

保留已有包绑定但尚无 compiler_version 字段的历史快照；未知版本不接受。只要包含版本 3 专用来源字段，就不能通过把版本号降为 1/2 或删除版本号绕过校验。

预检和定稿输出展示交付数量、剔除列表及原因。复用原三表下载协议，不增加第四个交付文件。

成功预检同样展示交付摘要，并可从页面重新打开；发布继续执行，不增加人工审批步骤。后续发布失败时展示失败原因。

## 选择

仅删除 JSON 节点无法处理依赖和历史哈希，不采用。改写内部目录/ID 会扩大到人工开关和历史映射，不在第一期实施。采用发布时投影，在保留原数据的同时生成可执行交付表。

## 验收

映射/未映射混合、同名重复工序、仅辅助工序、主干加工未命中特征、all/any/not 依赖化简、必要前置剔除、无关公共因素、三表 ZIP、旧版本冻结与防篡改均有回归验证。用真实 KMAI 引擎执行代表性 input 和相似场景；明确人工补参和严格孔型的输入边界。
