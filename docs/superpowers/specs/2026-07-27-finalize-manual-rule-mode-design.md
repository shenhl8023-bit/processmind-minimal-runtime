# 第四步人工规则模式设计

## 目标

在第四步规则无法可靠识别时，允许用户通过两个明确动作直接决定工序行为，避免反复改写自然语言。

## 交互

- `转为主工序`：当前工序始终进入路线，不再需要输入参数。
- `转为 Bool 条件`：创建一个由用户直接控制的布尔输入，默认标签为“是否需要{工序名}”。第五步选择“是”时纳入当前工序，选择“否”时不纳入。默认值为否。
- 两个动作固定显示在每张工序卡片中，包括已识别、已审核和折叠的主工序卡片。
- 已经是主工序时，“已是主工序”按钮禁用；已经是人工 Bool 条件时，“已是 Bool 条件”按钮禁用。
- Bool 条件允许用户在转换前修改开关名称，但不允许修改其控制的目标工序。
- 用户进入文字编辑后未作实际修改就保存时，只退出编辑，不写入草稿、不显示“已改”、不重新识别，也不使已导出的规则包过期。

## 数据与执行

- 人工模式不调用大模型。
- Bool 字段使用稳定的 `project_factor.manual_process_<hash>` 编码、`boolean` 类型和 `eq true` 条件。
- 人工规则通过后端接口直接校验、确认并持久化，来源标记为用户直接设定。
- 主工序通过同一接口清除旧候选并保存为明确的主线描述。
- 第五步沿用规则包输入字段自动生成逻辑，将布尔字段显示为开关。

## 验证

- Bool 为真时只纳入目标工序，为假时不纳入。
- 同一工序重复转换生成同一字段编码。
- 主工序转换后不再阻止导出。
- 转换会使旧规则包失效，必须重新审核导出。
- 主工序卡片折叠时仍能看到两种人工模式入口，进入文字编辑时自动显示编辑区。
