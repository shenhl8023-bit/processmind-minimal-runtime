# 第三步问答与第四步规则衔接设计

用户已在当前会话明确要求按讨论方案执行。保留现有布局、问答树和历史记录，不执行暂存的第二步改版。

目标：第三步交付有适用范围、加工对象、条件语义、依据和缺项的结构化草稿；只有用户确认完整草稿后，才作为第四步候选来源。第四步仍需执行原有确认与规则包验证。

方案：复用现有 RuleConditionCandidate。新增独立问答辅助接口和 RuleDraftPanel；原问题树即时响应，模型在分支结束、自由输入或手动检查时补缺。模型不得确认规则。草稿允许暂存；数值/关系不完整、用户声明不确定、未知工序引用等阻止确认。使用已有规则校验器。适用范围以显式动态布尔条件进入条件规则；对象必须在属性字段语义中保留，模型不能把不同对象条件合并为整件属性。

知识：内置审核后的03/06/09术语、05/08场景、11关系语义及13重复辅助工序原则，附源文件和节名。10/13中未经确认的精度和长径比阈值不进入候选知识。知识仅帮助追问，不替用户决定阈值。

持久化：review新增 analysis_draft_json；复用现有保存端点传递草稿。带草稿的 pending 保存而不删除，旧端点不带草稿时保持重置语义。确认保存 accepted 前服务端再验证，草稿更改清除旧第四步解析和确认。序列/工作流修改按既有版本检查；模型期间不持有数据库写锁。

性能：模型请求总截止20秒、零重试；按项目/路线/工作流/当前工序/问题轨迹/草稿输入/提示词和知识版本缓存、并发去重；仅缓存成功结果；前端丢弃旧请求结果。失败保留本地草稿并允许重试，不能变成已确认。

界面：取消无依据预选与自动采纳，保留选项；全样本出现显示样本稳定，必须确认范围；现有全局批量入口不再自动选第一项。新增草稿区展示范围、对象、条件、模型补问、缺项及来源；保存待补充/确认草稿。第四步展示范围、对象、缺项和返回第三步入口，优先复用匹配的已确认第三步候选。

验证：结构工序、多因素精加工、清洗/检验依赖；AND/OR、排序与触发区别、不确定/数值缺项、非法ID、模型不可用、缓存和迟到结果、保存/重载/重置、第四步无重新推断、变更使旧确认失效。全量API/UI测试和生产构建。
