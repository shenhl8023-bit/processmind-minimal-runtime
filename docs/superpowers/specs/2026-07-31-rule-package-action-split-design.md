# 规则包审核、发布与下载拆分设计

## 状态

- 日期：2026-07-31
- 状态：已确认
- 范围：第四步“规则定稿”顶部操作区及规则包发布、下载链路

## 背景

当前“审核并导出规则包”按钮串联了规则识别、候选确认、规则包构建、结构校验、KmAI 兼容性检查、发布新版本和浏览器下载。单个入口同时包含多种不同副作用，用户无法从按钮名称判断点击后哪些数据会被写入，也无法在不生成新版本的情况下重复下载已经发布的规则包。

本设计将流程拆成“规则审核”“发布规则包”“下载当前版本”三个独立操作。三个按钮分别对应审核结果写入、规则包版本写入和只读文件下载，使用户能够明确控制每一步。

## 目标

- 将当前复合按钮拆成三个职责单一的按钮。
- 允许重复下载当前已发布版本，且不重新审核、不重新发布、不生成新版本。
- 保留现有规则识别、安全候选自动确认、规则包校验和工作流版本保护。
- 当前规则变更后，阻止下载过期版本，并引导用户重新审核和发布。
- 保证发布与下载使用后端权威规则包快照。

## 非目标

- 不改变规则识别模型、标准因子目录或自动确认安全标准。
- 不改变规则包 V2 契约、KmAI 固定适配规则或第五步生成逻辑。
- 不在本次改造中提供历史版本列表或历史版本下载入口。
- 不合并或删除现有“重新识别全部”操作。

## 交互设计

### 操作顺序

第四步顶部操作区按以下顺序展示：

1. `规则审核`
2. `发布规则包`
3. `下载当前版本`

“重新识别全部”继续保留。它负责清空并重做普通规则识别；“规则审核”只处理当前待审核项，两者职责不同。

### 规则审核

“规则审核”负责：

- 识别尚未处理、来源内容已变化或标准因子目录版本已过期的规则。
- 自动确认满足现有安全条件、无歧义的候选规则。
- 保留成功处理的结果，并筛选、定位仍需人工处理的规则。

该操作不构建规则包，不调用编译接口，不发布版本，也不下载文件。

按钮状态：

- 存在待审核规则且标准因子目录可用时启用。
- 处理中根据阶段显示 `正在识别 x/y` 或 `正在审核 x/y`。
- 没有待审核项时显示 `规则已审核` 并禁用。
- 标准因子目录不可用或其他写操作正在进行时禁用。

### 发布规则包

“发布规则包”负责构建、检查和发布新版本：

1. 根据当前已确认规则构建规则包 V2 编译请求。
2. 调用后端编译接口，执行结构、测试用例、标准因子绑定和 KmAI 兼容性检查。
3. 打开“审核并发布规则包”弹窗。
4. 审核通过后启用 `确认发布`；审核未通过时展示阻断详情和第四步定位入口。
5. 用户确认后调用现有保存接口，创建并发布新版本。
6. 发布成功后只更新页面中的规则包 ID、版本、内容哈希和状态，不自动下载。

按钮状态：

- 所有需要确认的规则均已确认时启用。
- 当前规则内容已经存在对应的有效已发布版本时显示 `已发布 Vx` 并禁用。
- 当前规则内容变化或原规则包过期后重新启用。
- 发布处理中显示 `正在发布...`，并阻止重复提交。

### 下载当前版本

“下载当前版本”只下载当前规则对应的有效已发布版本：

- 不调用规则识别、规则确认、编译或发布接口。
- 可以重复下载同一个版本。
- 重复下载不改变规则包数量、版本、状态或发布时间。
- 当前规则内容变化、路线版本变化或没有已发布版本时禁用。
- 下载处理中显示 `正在下载...`。
- 禁用原因应通过相邻状态提示或工具提示说明，例如 `当前规则已变更，请先重新发布`。

顶部下载入口不允许下载已经取代或归档的历史版本。历史版本下载属于后续版本记录功能。

## 状态模型

前端保存当前已发布规则包的最小元数据：

- `id`
- `version`
- `route_version_id`
- `content_hash`
- `status`

当前版本有效必须同时满足：

- 状态为 `published`。
- 规则包关联当前路线版本。
- 当前规则编译内容哈希与已发布内容哈希一致。
- 当前需要确认的规则全部处于有效确认状态。

任一条件不满足时，已发布版本在第四步视为过期：禁用“下载当前版本”，启用“发布规则包”。

## 数据流

### 规则审核数据流

1. 找出需要重新解析的条件规则和工序关系。
2. 并发调用现有规则解析接口。
3. 找出满足批量安全确认条件的候选。
4. 并发调用现有规则确认接口，确认人继续记录为 `规则包整体审核`。
5. 保留成功结果，显示失败数量，并聚焦剩余待处理规则。

该流程允许部分成功，不执行事务级整体回滚。

### 发布数据流

1. 前端使用当前规则卡、标准字段和标准因子构建规则包 V2 请求。
2. 前端调用 `POST /api/extract/finalized-rule-packages/compile`。
3. 后端返回临时规则包、内容哈希、结构校验结果和 KmAI 兼容性结果；此时不保存规则包。
4. 前端展示发布审核弹窗。
5. 用户取消或审核未通过时终止，不调用保存接口。
6. 用户确认发布后，前端调用现有 `POST /api/extract/finalized-rule-packages`，并携带当前 `expected_workflow_revision` 和 `route_version_id`。
7. 后端再次验证工作流版本、路线归属、规则来源确认、规则包结构、包内测试、标准因子绑定和 KmAI 兼容性。
8. 后端创建新版本，将原发布版本标记为 `superseded`，将新版本标记为 `published`。
9. 前端使用保存接口返回的权威元数据更新页面，不生成 ZIP。

### 下载数据流

新增只读接口：

```text
GET /api/extract/finalized-rule-packages/{package_id}/download
```

接口行为：

- 只接受当前状态为 `published` 的规则包 ID。
- 从数据库中的已发布快照组装 ZIP，不接受前端提交规则包内容。
- 返回 `application/zip` 和带版本号的 `Content-Disposition` 文件名。
- 不修改规则包记录、版本号、状态、发布时间或工作流状态。

ZIP 内容与现有导出保持一致：

- `manifest.json`
- `input_schema.json`
- `route_catalog.json`
- `route_rules.json`
- `test_cases.json`
- `rule_report.md`
- `validation_report.json`
- `kmai-v1/factor_schema.json`
- `kmai-v1/factor_expansion_rules.json`
- `kmai-v1/route_catalog.json`
- `kmai-v1/route_rules.json`
- `kmai-v1/README-替换说明.txt`

KmAI 文件必须由已发布规则包快照和对应的兼容元数据生成，不能使用当前页面中的临时编译结果。

## 组件与代码边界

### `FinalizeView`

- 展示三个按钮及其状态。
- 调度规则审核、发布和下载流程。
- 保存当前已发布规则包元数据。
- 不负责 ZIP 文件组装。

### `useFinalizeRulePackagePublish`

从现有 `useFinalizeRulePackageExport` 中拆出并负责：

- 构建编译请求。
- 调用编译接口。
- 请求发布审核确认。
- 调用规则包保存发布接口。
- 处理发布冲突和发布失败。

该组合函数不得调用浏览器下载函数。

### `useFinalizedRulePackageDownload`

负责：

- 请求指定已发布规则包的 ZIP。
- 从响应头读取权威文件名，缺失时使用项目名和版本号生成回退文件名。
- 触发浏览器保存。
- 管理下载中状态和下载错误。

该组合函数不得调用编译、规则确认或发布接口。

### `RulePackagePublishReviewDialog`

由当前 `RulePackageExportReviewDialog` 调整而来：

- 标题改为 `审核并发布规则包`。
- 说明明确确认后只发布，不自动下载。
- 主按钮改为 `确认发布`。
- 继续支持 `ready` 和 `blocked` 两种审核状态。
- 阻断项继续支持定位到第四步对应规则卡。

### 后端归档服务

新增独立归档服务，负责从持久化规则包模型生成 ZIP 字节和文件名。路由只负责读取记录、检查状态并返回文件响应，避免在路由中复制归档格式逻辑。

## 异常与并发处理

- 规则审核部分失败：保留成功结果，展示成功数、失败数和剩余规则。
- 标准因子目录不可用：禁用规则审核和发布，保留现有编辑。
- 规则包构建失败：以阻断审核结果展示具体工序、来源和错误，不调用发布接口。
- 编译或 KmAI 检查失败：禁止确认发布，允许返回第四步定位处理。
- 用户取消发布：不保存规则包，不下载文件；此前已完成的规则审核结果继续保留。
- 发布时工作流修订号冲突：不创建版本，提示页面状态过期并重新加载第四步。
- 发布网络失败：保留审核状态，允许重新点击发布。
- 下载版本不存在或状态不再为 `published`：刷新规则包状态并禁用下载入口。
- 下载网络失败：不改变已发布版本，允许直接重试下载。
- 归档生成失败：返回明确错误，不返回不完整 ZIP。
- 审核、发布和下载分别维护 `reviewing`、`publishing`、`downloading` 状态；写操作进行时禁用其他写操作，下载只允许单次在途请求。

## 测试设计

### 前端单元测试

- “规则审核”只调用解析和确认接口，不调用编译、发布或下载。
- “规则审核”部分失败时保留成功结果并展示剩余数量。
- “发布规则包”调用一次编译并展示发布审核弹窗。
- 取消发布不调用保存接口。
- `blocked` 审核不能确认发布。
- `ready` 审核确认后只调用一次保存接口，不调用下载。
- 当前内容已经发布时显示 `已发布 Vx` 并禁用再次发布。
- “下载当前版本”只调用归档下载接口。
- 多次下载同一版本不会调用编译或发布接口。
- 当前规则内容变化后禁用下载并启用发布。
- 审核、发布、下载进行中均阻止重复触发。
- 下载失败不会改变页面中的已发布版本元数据。

### 后端测试

- 只有 `published` 状态规则包可以下载。
- 不存在、`superseded` 或 `archived` 状态返回明确错误。
- 下载响应类型、文件名和版本号正确。
- ZIP 包含全部 V2、校验报告和 KmAI 文件。
- ZIP 文件内容来自已发布数据库快照。
- 重复下载前后规则包数量、版本、状态和发布时间不变。
- 归档生成异常不会返回部分 ZIP。

### 集成验收

1. 使用“规则审核”完成全部规则确认。
2. 使用“发布规则包”发布 V1，发布成功后不自动下载。
3. 使用“下载当前版本”重复下载 V1，多次下载后数据库仍只有 V1。
4. 修改任意规则后，V1 顶部下载入口立即不可用，发布按钮重新启用。
5. 重新审核并发布后生成 V2。
6. 重复下载只下载 V2，不产生 V3。
7. 在桌面和窄屏布局下，按钮、处理中数字和版本文字不重叠、不溢出操作区。

## 完成标准

- 第四步不再出现“审核并导出规则包”复合按钮。
- 顶部明确展示“规则审核”“发布规则包”“下载当前版本”三个操作。
- 发布成功不触发自动下载。
- 下载当前版本不产生任何数据库写入或新版本。
- 当前规则变更后不能通过顶部入口下载过期版本。
- 三条流程职责独立，并有自动化测试防止接口串用。
- 前端单元测试、类型检查、生产构建和相关后端测试通过。
