# 项目级通用分组模板导入设计

## 目标

将第二步“模板分组映射”从固定套筒模板改为项目级通用功能。用户首次进入时上传一个 Kmsoft 分组模板 XML，系统解析唯一零件下的递归分组结构和每个分组的“特征选择”，确认后长期保存到当前项目。再次进入直接复用；用户可主动更换模板。

普通用户只上传分组模板 XML。系统内置并版本化管理 `FeatureTemplate.xml`，用它校验分组模板引用的特征名称。

## 已确定原则

- 每个分组模板 XML 只允许一个 `Item type="Part"`。
- XML 原始 `id` 不作为业务身份；分组完整名称路径是业务身份。
- 同一父分组下禁止同名子分组，避免完整路径产生歧义。
- 分组名称、完整路径和“特征选择”是映射的核心信息。
- 项目首次上传后长期复用，只在用户点击“更换模板”时重新上传。
- 更换模板时按完整名称路径迁移旧映射；路径不存在的映射失效。
- 复合工序、低置信度结果和歧义结果必须人工确认。
- 大模型只能从当前模板解析出的候选分组键中选择。

## 用户流程

### 首次进入

用户点击“模板分组映射”后，如果当前项目没有已确认模板，弹窗进入上传状态，只接受 `.xml` 文件。

上传后先调用预览接口。预览页显示：

- 原始文件名和检测到的编码。
- 零件文件名。
- 分组数量、非空特征选择数量和校验问题数量。
- 递归分组树。
- 每个分组引用的特征选择标签。

校验通过后，用户点击“确认并进入映射”。系统正式保存模板，并进入现有映射工作台。

### 再次进入

项目已有模板时直接进入映射工作台。页头显示模板文件名、零件文件名、分组数量和特征选择数量，并提供“更换模板”命令。

### 更换模板

新文件先走同样的预览与校验流程。确认前系统按完整名称路径比较新旧模板并显示：

- 可继续保留的映射数量。
- 因路径不存在而失效的映射数量。
- 失效映射对应的工序和旧分组路径。

用户确认后，模板与映射迁移结果一起生效。取消时项目当前模板和映射保持不变。

## XML 解析

### 输入限制

- 支持 XML 声明或内容检测得到的 GB2312、GB18030 和 UTF-8。
- 只接受 `.xml` 文件，并设置保守的文件大小上限。
- 拒绝 DTD、外部实体和无法完整解析的 XML。
- 根节点必须为 `<Kmsoft>`。
- 必须存在 `Part_Template`、`Group_Template` 和唯一 `Part`。
- 唯一 `Part` 下必须至少包含一个 `Group`。

### 分组结构

递归读取 `Item type="Group"`。分组显示名称来自其 `Params` 下：

```xml
<param name="名称" value="A侧" />
```

节点结构为：

```json
{
  "key": "按规范化完整路径生成的稳定键",
  "source_id": "XML 中的原始 id，仅用于追踪",
  "name": "孔",
  "path": ["A侧", "孔"],
  "feature_selections": ["孔(盲孔)"],
  "params": {
    "依赖方向": "从父",
    "依赖方式": ""
  },
  "children": []
}
```

路径中的每个名称执行去除首尾空白和 Unicode NFC 规范化。`key` 根据规范化路径数组的规范 JSON 计算 SHA-256，并使用 `grp_` 加固定长度摘要作为值；不能通过连接带分隔符的字符串计算，也不能使用 XML `id`。同一父节点出现相同规范化名称时阻止导入。

### 特征选择

“特征选择”来自 Group 的参数：

```xml
<param name="特征选择" value="外倒角,回转面倒圆" />
```

解析规则：

- 使用英文逗号拆分。
- 对每项去除首尾空白。
- 保持原始顺序并去重。
- 空值合法，常用于方向或区域父分组。
- 每个非空值必须存在于内置 `FeatureTemplate.xml` 的任意 `Item name` 中。
- 未找到的值是阻止确认的校验错误，错误必须包含分组完整路径和非法值。

内置特征字典保存内容哈希作为 `feature_dictionary_version`。解析结果记录使用的字典版本，便于后续追踪。

## 后端数据

新增项目一对一分组模板记录，至少包含：

- `project_id`
- `original_filename`
- `source_encoding`
- `part_filename`
- `content_hash`
- `feature_dictionary_version`
- `source_xml`
- `tree_json`
- `validation_json`
- `mappings_json`
- `template_revision`
- `group_count`
- `feature_selection_count`
- `created_at`
- `updated_at`

原始 XML 统一解码为 Unicode 后保存；解析结构和当前正式映射以 JSON 保存。`template_revision` 从 `1` 开始，模板替换或正式映射更新时原子加一，用于阻止旧页面覆盖新数据。上传接口不读取用户机器或 KMAI 安装目录中的任意路径。

## API

### 预览

`POST /api/extract/group-templates/preview`

使用 multipart 上传 XML。接口只解析和校验，不修改项目数据，返回规范化模板结构、统计信息、校验错误以及内容哈希。

更换模板时，前端使用预览返回的新路径集合与当前正式映射比较，在确认前展示可保留和将失效的映射清单。后端确认接口会重新执行同一比较，不信任前端计算结果。

### 当前模板

`GET /api/extract/group-templates/current?project_id={id}`

项目没有模板时返回 `404`；已有模板时返回保存的结构化模板、当前正式映射、模板修订号和元数据，不返回不必要的原始 XML。

### 确认或更换

`PUT /api/extract/group-templates/current`

使用 multipart 提交 `project_id`、XML 文件、预览阶段得到的 `expected_content_hash` 和 `expected_template_revision`。后端重新解析文件并核对内容哈希，防止预览与确认不是同一内容，然后原子保存模板。

项目首次确认模板时 `expected_template_revision` 必须为 `0`；项目已有模板时必须提交当前接口返回的修订号。这样首次上传、重复提交和模板替换都使用同一套乐观并发控制。

后端以当前项目正式映射为准，按新模板路径原子迁移映射。响应返回可保留与失效的映射清单和新修订号。模板保存失败时不得部分修改旧模板或映射。请求修订号过期时返回 `409`，要求页面重新加载。

### 保存映射

`PUT /api/extract/group-templates/mappings`

提交 `project_id`、`expected_template_revision` 和完整映射集合。后端验证每条完整路径存在于当前模板，补充稳定键、分组名和特征选择，然后原子替换正式映射并增加模板修订号。浏览器本地存储只用于未保存草稿恢复，不再作为正式映射的数据源。

### 智能建议

现有 `POST /api/extract/template-group-mappings/suggest` 不再接收或依赖固定模板树。候选分组由当前项目已确认模板产生，每个候选包含稳定键、完整路径、分组名和特征选择。

后端继续校验大模型返回的候选键；不存在于请求候选中的键一律拒绝。

## 前端结构

将固定 `BUSHING_11_TEMPLATE_TREE` 替换为 API 返回的项目模板树。

模板映射弹窗包含三种主状态：

1. `empty`：上传 XML。
2. `preview`：展示解析与校验结果，允许重新选择或确认。
3. `workspace`：展示动态分组树和待映射工序。

工作台要求：

- 展示所有父、子分组。
- 分组名称旁显示“特征选择”标签；空特征不显示占位标签。
- 手工映射允许选择任意分组。
- 页头显示当前模板摘要和“更换模板”命令。
- 智能映射期间仍立即展示程序候选。
- 模板或建议接口失败时保留手工映射能力。
- “保存映射”仍是映射关系的明确保存点。
- 保存成功后使用后端返回的正式映射和新模板修订号刷新本地状态。

## 通用智能映射

删除针对套筒、A/B 侧和固定 UUID 的候选依赖。候选生成改为模板驱动：

1. 从当前模板收集所有可选分组。
2. 优先将具有非空“特征选择”的分组加入智能候选。
3. 使用工序名称和工步内容与分组名称、完整路径、特征选择做规范化词项匹配。
4. 将受控候选交给大模型补充语义判断。
5. 大模型只能返回已有稳定键，且证据必须来自工序名称或工步原文。
6. 唯一且高置信度的单特征结果可以自动应用。
7. 多特征复合工序、多个同等候选、低置信度和无可靠证据结果保留人工确认。
8. 当前手工选中的分组永远不能作为智能映射兜底。
9. 已有人工映射永远不能被智能映射覆盖。

## 映射与导出兼容

新的映射元数据至少包含：

- `source_operation_id`
- `alias`
- `template_group_key`
- `template_group_name`
- `template_group_path`
- `feature_selections`

读取旧数据时：

- 优先使用旧数据中的 `template_group_path` 在当前模板中查找节点。
- 找到路径后生成新的稳定键并补充特征选择。
- 路径不存在时将该映射标记为失效，不使用旧 XML ID 猜测。

现有浏览器草稿和已保存路线中的旧映射只在项目尚无正式模板映射时执行一次迁移；迁移确认后以后端项目模板记录为准。

第二步保存路线、第四步规则包和 KMAI 兼容导出继续携带模板分组元数据。KMAI v1 仍可忽略未知附加字段，不改变现有路线执行合同。

## 错误处理

阻止预览确认的错误包括：

- 文件类型或大小不合法。
- 编码无法识别。
- XML 不完整、包含禁用结构或根节点错误。
- 缺少模板定义节点。
- 零个或多个 Part。
- 没有 Group。
- 分组缺少名称。
- 同一父节点下分组重名。
- 特征选择不在内置字典中。

错误信息必须定位到文件和分组完整路径。模板替换失败时保留当前已确认模板和全部旧映射。

## 不在本期范围

- 在线编辑或生成分组模板 XML。
- 从 KMAI 安装目录自动读取模板。
- 普通用户每次映射时上传 `FeatureTemplate.xml`。
- 一个 XML 包含多个 Part 时提供 Part 选择器。
- 使用 XML UUID 迁移映射。
