# 规则包导出审核弹窗设计

## 目标

将第四步“审核并导出规则包”的 KmAI 映射弹窗改造成统一的中文导出审核入口。每次点击按钮都必须先展示审核结果，用户明确确认后才能发布并下载规则包。

## 当前问题

- 现有弹窗包含英文标题、说明、字段标签、按钮和错误信息。
- 弹窗只在编译发现未映射 KmAI 因子时出现；检查通过时会直接保存并下载。
- 用户在正常导出时没有最终确认机会，无法在发布前查看本次导出的摘要。

## 交互流程

1. 用户点击“审核并导出规则包”。
2. 系统继续执行现有的批量规则识别和安全候选确认。
3. 系统构建并编译规则包，执行结构校验和 KmAI 兼容性检查，但此时不保存规则包、不生成下载。
4. 系统每次都打开中文审核弹窗：
   - 检查通过时显示“审核通过”及规则包摘要。
   - 存在 KmAI 未映射值时，在同一弹窗中显示映射处理项。
   - 存在不能在弹窗中修复的问题时，显示未通过状态和中文检查详情，不允许确认导出。
5. 用户点击“取消”或关闭弹窗时，中止本次操作，不保存、不下载。
6. 用户点击“确认导出”后：
   - 没有映射修改时，直接使用已经审核的编译请求进入发布流程。
   - 有映射修改时，先保存映射并重新编译；重新检查通过后才进入发布流程。
7. 后端保存并返回权威规则包快照后，前端生成并下载 ZIP。

## 弹窗内容

### 通用区域

- 标题：`审核并导出规则包`
- 说明：`请确认本次规则包的审核结果。确认后将发布并下载规则包。`
- 摘要：项目名称、工序数量、规则数量、规则校验状态、KmAI 兼容状态。
- 次要操作：`取消`
- 主要操作：`确认导出`
- 处理中状态：`正在检查...`、`正在保存映射...`、`正在导出...`

### 审核通过状态

- 显示“审核通过”。
- 不展示全部既有 KmAI 映射，避免正常导出时出现冗长列表。
- 启用“确认导出”。

### 映射待处理状态

- 每个来源值展示来源字段、来源值、影响规则数量和规则位置。
- “作用范围”“处理方式”“绑定已有因子”“创建手工布尔因子”等文案全部使用中文。
- 映射选择完整后启用“确认导出”。点击后才保存映射并执行预览与重新编译；任一步失败都不发布规则包。
- 创建手工因子时，明确提示 KmAI 运行时需要通过 `manual.factor_overrides` 提供 `true/false`。

### 审核未通过状态

- 显示中文错误标题、摘要和可展开的检查详情。
- 禁用“确认导出”，只允许取消或关闭后返回规则页面处理。

## 组件与数据边界

- 新建 `RulePackageExportReviewDialog` 作为统一导出审核弹窗，使其同时支持“审核通过”“映射待处理”“审核未通过”三种状态；现有 KmAI 映射表单逻辑迁入该组件。
- `useFinalizeRulePackageExport` 负责预编译、校验、保存和下载，不直接决定弹窗布局。
- `FinalizeView` 负责连接导出流程和弹窗 Promise：确认后继续，取消后终止。
- 编译请求在用户确认前保持不变；映射保存成功后必须重新编译，避免下载旧的 KmAI 文件。
- 最终 ZIP 继续使用后端保存接口返回的权威 KmAI 文件，不使用确认前的临时编译文件。

## 错误处理

- 加载 KmAI 因子目录失败时显示中文错误，并禁用确认。
- 映射保存或预览失败时保留弹窗和用户选择，显示中文错误，允许重试。
- 映射保存后重新编译仍不兼容时不发布、不下载，并显示中文检查详情。
- 发布失败或工作流版本冲突继续沿用现有保护逻辑，但所有面向用户的文案改为中文。
- 防止重复点击造成两个审核弹窗或两次发布。

## 测试标准

- 兼容性检查通过时，每次调用导出都先请求用户确认。
- 用户确认前不会调用保存接口或下载函数。
- 用户取消后不会保存或下载。
- 用户确认后只保存一次并下载一次。
- 存在映射问题时，保存映射、重新编译并通过后才导出。
- 映射后仍不兼容时不会保存规则包或下载。
- 弹窗主要状态和错误路径不再出现面向用户的英文文案。
- 前端单元测试、类型检查和生产构建通过。

## 非目标

- 不展示或编辑全部既有 KmAI 映射；长期映射管理仍在“系统模型配置 > KmAI 映射”。
- 不改变规则识别、KmAI 映射优先级或后端规则包格式。
- 不自动接受语义不明确的 KmAI 因子映射。
