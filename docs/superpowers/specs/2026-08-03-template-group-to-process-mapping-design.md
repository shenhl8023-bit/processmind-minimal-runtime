# 模板分组到工序工步映射设计

## 目标

模板 XML 中的叶子分组及其特征选择，是系统识别零件几何特征后的入口；工序和
工步是由这些特征触发的结果。因此模板映射工作台改为以叶子分组为审核单位：

```text
模板叶子分组（特征） → 加工工序 → 具体工步
```

运行时根据命中的模板分组，读取其关联的加工工序和工步，生成对应工艺。一个
叶子分组可关联多个工步；同一工步也可服务多个叶子分组，关系本质为多对多。

## 当前问题

当前界面虽然左侧显示模板树，但保存完整性、顶部进度和右侧主列表均以“所有
工步必须处理”为中心。截图中的“已处理 0 / 59 个工步”、正常化和调质均要求
标记“不依赖模板特征”，会让用户把大量时间花在无关操作上。

现有 `step_mappings_json` 已同时保存分组路径和工步稳定键，可以继续作为关系边
存储；本次不需要改变 XML、规则包格式或 KMAI 代码。

## 方案选择

### 工步主导

逐个工步寻找分组。优点是记录天然以工步为键；缺点是审核范围过大，业务方向
与运行时相反，不适合继续使用。

### 分组 × 工序矩阵

一次展示所有分组和工序。少量数据时直观，但真实模板分组与工序较多时会迅速
变成难以阅读和维护的表格。

### 分组主导双栏工作台

采用该方案。左侧提供模板树导航，右侧只展示当前叶子分组可以关联的加工工序
和工步。用户按零件特征逐个配置，关系方向与实际执行一致。

## 资格筛选

候选工步按工步文本判断，而不是只按工序容器名称判断。

- 直接加工几何特征的工步进入候选：车、铣、钻、镗、铰、磨、研、珩、攻丝、
  切槽、挖槽、倒角、倒圆、成形、特种加工等。
- 热处理、清洗、除油、测量、检验、探伤、包装、标记、装配等默认不显示。
- 不能只因出现“孔”“面”“槽”等名词就视为加工；例如“检查孔径”不应等同
  于“钻孔”。
- 一个工序容器只在至少存在一个候选加工工步时显示，展开后仍只显示这些工步。
- 通过“显示其它工步”次要入口允许用户在特殊工艺中手动加入被过滤项，避免
  受固定工艺术语限制。

资格词库集中维护并配套纯函数测试；它只控制默认展示，不限制用户建立合法的
正式关联。

## 界面设计

### 左侧：模板特征分组

- 父分组用于展开、定位和汇总，不能作为正式映射目标。
- 叶子分组显示特征选择、已关联工步数量和状态：`已配置` 或 `未配置`。
- 点击叶子分组后，右侧切换到该分组的关联编辑状态。
- 点击父分组仅显示其后代叶子的配置汇总，不触发正式映射。
- 顶部进度改为“已配置 X / Y 个叶子分组”，不再显示“已处理 X / Y 个工步”。

### 右侧：当前分组的关联加工工序

- 标题明确展示当前路径，例如“为 A侧 / 孔 关联加工工序”。
- 标题下方显示该分组的特征选择，如“孔（盲孔）”。
- 仅列出含候选加工工步的工序容器，用户展开后勾选具体工步。
- 已关联工步显示为勾选状态；同一工步在其它分组中仍可再次勾选。
- 提供“智能推荐当前分组”，不再提供“重新识别全部工步”。
- 推荐仅针对当前分组运行，程序候选先出现，模型排序在后台补充，失败不遮挡
  工作台也不清除程序候选。

### 完整性与保存

- 叶子分组允许保持“未配置”；它表示该模板特征在当前标准路线中没有需要关联
  的加工工步，而不是错误。
- 保存时若存在未配置叶子，只显示汇总提示，例如“12 个叶子分组中有 4 个未配置”，
  允许用户直接保存，不要求逐条确认。
- 正式映射记录只保存 `confirmed` 的分组—工步关系；不再为了凑齐工步审核而
  生成批量 `not_applicable` 记录。
- 旧的用户明确 `not_applicable` 记录不作为主界面任务显示；载入时保留兼容，
  下一次保存时不再生成新的同类自动跳过记录。

## 数据与接口

当前正式记录继续包含：

- 工序 ID、名称、工步序号、工步文本和稳定工步键。
- 目标叶子分组路径、稳定分组键和该叶子的受控特征选择。
- `confirmed` 状态、置信度、来源和模板修订号。

界面以分组路径反向索引这些记录：`group key → step mappings[]`。保存时再写回现有
`PUT /api/extract/group-templates/step-mappings`，因此无需数据库迁移。

智能推荐接口调整为“给定叶子分组和加工候选工步，返回排序后的候选工步”。模型
只能从程序提供的稳定工步键中选择，不能创建工序、工步、分组路径或特征。模型
结果需带原文证据和置信度，低置信度仅显示为建议，不自动写入正式映射。

## 草稿、失效与兼容

- 草稿仍绑定项目、模板修订号和完整路线指纹；路线或工步文本变化时立即失效。
- 模板更换后按叶子路径和特征合法性尝试保留关系，无法对应的映射回到未保存草稿。
- 第二步重新推理保留 XML，但清空正式映射和本地草稿。
- 已有 `confirmed` 映射加载后直接显示在对应叶子分组下。
- 旧工序级别名与兼容导出维持原状，不在本次范围内变更。

## 错误处理

- 模型不可用、超时或返回无效结果：保留程序候选，提示“智能排序不可用，可直接
  手工关联”，不阻断保存。
- 选择父分组作为目标：服务端继续拒绝，只有带合法特征的叶子可建立正式关系。
- 伪造特征或非叶子路径：服务端继续按模板树验证并拒绝。
- 同一工步关联多个叶子：允许保存；同一分组重复关联同一工步时去重。

## 验证

- 仅有候选加工工步的工序容器出现在右侧。
- 正常化、调质、清洗、检验、包装和标记不进入默认候选。
- “钻孔”进入候选而“检查孔径”不进入候选。
- 选择 A侧 / 孔 可同时关联钻孔、镗孔和铰孔。
- 同一车槽工步可在外环槽与内环槽两个叶子下同时存在。
- 父分组不能被保存为目标；叶子无配置时可保存并显示汇总提示。
- 推荐失败仍可手工建立关系；关闭重开后正式关系按叶子恢复。
- 全量 API 测试、前端 Vitest、类型检查、生产构建和浏览器流程通过。

## 非目标

- 不改变 Kmsoft XML 分组结构或特征字典。
- 不修改 KMAI 代码、兼容层或规则包外部格式。
- 不让模型直接保存、确认或发布映射关系。
