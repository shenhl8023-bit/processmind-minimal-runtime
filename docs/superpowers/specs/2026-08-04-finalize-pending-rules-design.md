# 规则定稿待处理状态统一设计

## 目标

规则定稿页中，只要仍有非主线规则未完成当前版本的人工确认，“仅看需处理”必须展示对应工序，页面不得显示“当前没有需要处理的规则”或“全部就绪”。

## 现状问题

批量审核完成后的剩余数量使用“非主线且没有当前已确认规则”计算；待处理筛选却把“已识别、待人工确认”的候选排除。两套判断导致同一工序同时被提示为“需要人工处理”又被待处理列表隐藏。

## 设计

- 在规则包工具层提供统一的 `needsFinalizeRuleReview(item, registryVersion?)` 判断。
- 主线规则不需要确认；条件、关联和待补充规则在没有当前版本已确认结果时都属于待处理。
- 待处理筛选、导航提示、批量审核后的剩余列表和发布就绪判断统一使用该函数。
- 顶部进度统计真正已确认的条件/关联规则，文案使用“已确认 X/Y”；只有全部确认后显示“全部已确认”。
- 真正没有待处理规则时，空状态说明改为“系统已完成全部规则审核”。

## 边界

- 不改变后端规则协议、批量自动确认安全条件或发布校验。
- 不改变主线规则无需人工确认的现有语义。
- 发布校验定位出的额外阻断卡片仍可被强制加入当前筛选结果。

## 验收标准

1. `pending_confirmation` 且未自动确认的规则出现在“仅看需处理”中。
2. 待处理数量、筛选列表和批量审核提示使用同一规则集合。
3. 存在待人工确认规则时，顶部不显示“全部已确认”。
4. 所有规则确认后，待处理列表为空并显示完成态。
5. 相关 Vitest、TypeScript 检查和前端构建通过。
