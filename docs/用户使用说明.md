# ProcessMind 用户使用说明

本文面向工艺工程师、规则审核人员和负责本地部署的技术人员，按当前最小可运行包的页面和启动脚本编写。系统没有账号体系，默认只监听本机地址；需要在内网共享时，请在外层增加访问控制和网关。

## 1. 先了解几个概念

| 概念 | 含义 |
| --- | --- |
| 任务 | 一组独立的工艺规程资料、路线分析结果和规则版本。系统按任务保存工作流状态。 |
| 主资料 | 用于提炼典型路线的工艺规程文件，当前支持 PDF、DOCX、XLSX 及约定结构的工艺路线 JSON。 |
| 标准化母路线 | 从多份规程中归并出的统一工序顺序，是后续规则分析的基础。 |
| 规则分析 | 针对每道工序确认它在什么材料、结构、精度或要求下出现。 |
| 模板映射 | 把需要按零件特征判断的工步关联到 Kmsoft XML 分组模板。 |
| 规则包 | 把路线和已确认规则编译成可执行版本。草稿和未发布结果不能用于正式生成。 |
| 验证生成 | 输入一个零件的条件，让已发布规则包输出工序和工步。 |

建议先按“上传资料 → 路线归并 → 规则分析 → 模板映射 → 规则定稿 → 验证生成”走完一个小样本，再扩大到完整资料集。

## 2. 准备环境并启动

### 2.1 本地开发运行

本地运行建议准备 Python 3.11+、Node.js 20+ 和 npm 10+。首次运行在项目目录执行：

~~~bash
./bootstrap.sh
~~~

脚本会创建后端虚拟环境并安装依赖，再安装前端依赖。随后开两个终端：

终端一启动后端：

~~~bash
./start-api.sh
~~~

终端二启动前端：

~~~bash
./start-ui.sh
~~~

默认地址：

- Web：<http://127.0.0.1:5173>
- API：<http://127.0.0.1:8000>
- API 文档：<http://127.0.0.1:8000/docs>

若端口已占用，可在启动前设置 <code>PROCESSMIND_API_PORT</code> 或 <code>PROCESSMIND_UI_PORT</code>；前端代理会跟随 API 端口。启动脚本只绑定 <code>127.0.0.1</code>，关闭终端会停止对应进程。

### 2.2 Docker 运行

在项目目录执行：

~~~bash
cp .env.compose.example .env
docker compose up -d --build
~~~

默认 Web 地址为 <http://127.0.0.1:8080>，停止服务：

~~~bash
docker compose down
~~~

Web 端口可以通过 <code>.env</code> 中的 <code>PROCESSMIND_WEB_PORT</code> 调整。Docker 将宿主机 <code>./data</code> 挂载到容器的 <code>/runtime-data</code>，因此数据库和上传文件会保留在项目的 <code>data/</code> 目录。

### 2.3 Windows 普通交付包

双击 <code>start-windows.cmd</code> 启动，双击 <code>stop-windows.cmd</code> 停止。首次启动会检查运行时和前端依赖，按窗口提示完成初始化。具体包是否包含便携运行时，以交付包内文件为准。

### 2.4 Windows 7 SP1 离线包

Win7 包使用独立的 Python 3.8.10 运行时，目标机不需要安装 Python 或 Node.js。目标机需要：

1. 预装 Chrome 109 或 Edge 109。
2. 以管理员身份运行 <code>prerequisites\install-kb2533623.bat</code>，安装完成后重启。
3. 解压交付 ZIP 后双击 <code>start-win7.bat</code>。

辅助命令：

~~~text
status-win7.cmd    查看 API 健康状态
stop-win7.cmd      停止当前包启动的 API
~~~

三个命令执行后均保留窗口，便于查看报错；按任意键只关闭命令窗口。API 在后台运行，启动完成后没有单独的 API 控制台窗口。自动化调用前执行 <code>set "PROCESSMIND_NO_PAUSE=1"</code>，再使用 <code>call start-win7.bat --no-browser</code>、<code>call status-win7.cmd</code>、<code>call stop-win7.cmd</code>。

状态命令只有服务健康且归属当前目录时返回 0，否则返回 1。关闭命令成功停止或确认已退出时返回 0；无法确认归属、权限不足或关闭失败时返回 1 并保留可重试的状态。不要用 <code>taskkill /IM python.exe</code> 关闭系统。自定义端口启动传入 <code>--port 18087</code>；状态和关闭默认读取状态文件里的端口，状态丢失时可显式传入同一端口。不同解压版本共用默认运行目录时，请先从原目录关闭，再启动新包。

启停和状态命令对同一运行目录互斥；提示“另一个命令正在执行”时请等待前一个命令结束后重试。无法读取匹配当前目录的进程命令行时，启动器保留状态并返回失败，不会仅凭端口或健康接口认定进程归属。

Win7 包默认把数据库、上传文件、日志、缓存和 PID 写入 <code>%LOCALAPPDATA%\ProcessMind</code>，可用同名环境变量 <code>PROCESSMIND_RUNTIME_DIR</code> 指向其他可写目录。关闭浏览器不会停止 API，需要执行 <code>stop-win7.cmd</code> 完全退出。

## 3. 第一次配置模型

1. 打开 Web 页面，点击顶部的“模型设置”。
2. 填写“API 基础路径”。它应是模型服务的 OpenAI 兼容接口地址，例如 <code>https://api.deepseek.com/v1</code>；不要把本项目的 <code>/api</code> 地址填在这里。
3. 填写“API Key”。已保存的密钥会被隐藏；更新时输入新值，保持原值时留空，必要时可点击“清空已保存密钥”。
4. 填写“默认模型”。首次配置或刚更换服务地址时直接手动输入模型名；刷新图标读取的是已保存配置对应的模型列表，建议先测试并保存，再按需刷新。
5. 点击“测试连接”，确认服务能返回，再点击“保存设置”。

模型配置用于路线提炼、智能推荐、规则识别和知识库回答。模型服务不可用时，页面会显示具体错误；不要把真实密钥写入 Git、压缩包或截图。部署环境也可以通过 <code>.env</code> 或环境变量注入 <code>LLM_API_URL</code>、<code>LLM_API_KEY</code>、<code>LLM_MODEL</code>。

## 4. 新建任务并准备资料

### 4.1 新建或选择任务

1. 进入“上传资料”。
2. 点击“新建任务”，填写任务名称，例如 <code>42CrMo 主轴加工</code>，点击“确认创建”。
3. 在任务卡片中点击任务名称切换当前任务。顶部工作流和后续页面都会使用当前任务。
4. 删除任务时先点击任务卡片上的删除按钮，再在确认框中点击“确认删除”。删除会同时清理该任务的文档和提炼结果，无法恢复；正式删除前请先备份实际运行中的数据库、上传目录和设置文件。

### 4.2 上传主资料

在“典型工艺规程文件”卡片中点击或拖拽文件，支持：

~~~text
.pdf  .docx  .xlsx  .json
~~~

旧版 `.doc` / `.xls` 请先另存为 `.docx` / `.xlsx`。Word、Excel 的工序工步明细需要模型配置可用；无法核对原文或没有工步时会提示修正，不会用空工步继续映射。

JSON 支持以下两种结构，不能把任意 JSON 当成工艺规程：

~~~json
{
  "零件名称": "样例轴",
  "工艺路线": [
    {"工序号": 10, "工序名称": "下料", "工步内容": ["棒料锯切"]},
    {"工序号": 20, "工序名称": "车削", "工步内容": ["车外圆", "倒角"]}
  ]
}
~~~

工序号须为严格递增的正整数，不能重复；每道工序必须有非空的工步文本数组，可选填写文本字段“设备类型”和“设备型号”。也可使用顶层“工序→工步”字典，例如：

~~~json
{"车削": {"车外圆": "车外圆至20mm&&CA6140&&NULL", "倒角": "倒角C1&&NULL&&NULL"}}
~~~

字典中的工序和工步按文件顺序读取，工步描述最多由“内容&&设备&&备注”三段组成；没有设备或备注时可用 `NULL`。

可以一次选择多份文件，也可以点击“继续添加文件”补充。当前后端默认限制为单次最多 20 个文件、单文件 50 MB、单批次 200 MB；超过限制时按提示分批上传。

上传完成后，文件会出现在列表中。误传文件可以点击文件右侧的删除按钮；如果还没有主资料，底部“进入路线归并”按钮会保持禁用。

### 4.3 参考资料的当前边界

后端保留参考资料接口，支持资料文件和在线编写的补充要求；但当前最小运行包的第一步默认隐藏“参考资料”卡片（页面代码中的 <code>showReferencePanel</code> 为关闭状态）。如果你的交付版本显示该卡片，可以上传补充资料或点击“在线编写”保存工艺要求；如果页面没有该卡片，请把补充要求合并到主资料或由审核人员在后续规则中人工补充，不要把它当成当前界面必有的入口。

## 5. 六步业务流程

### 5.1 第一步：上传资料

完成任务选择和主资料上传后，确认文件数量、文件名和格式无误，点击底部“进入路线归并”。系统只会把当前任务的主资料带入后续提炼。

### 5.2 第二步：路线归并

1. 进入页面后点击“开始 AI 智能提炼”。系统会显示提炼阶段和进度；处理时间取决于文件数量、页数和模型响应。
2. 如果出现“分析出错”，先阅读错误面板和 Harness 校验信息，再点击“重试”。确认 API、模型和资料内容可用后再重试，不要连续重复提交。
3. 提炼完成后，页面分为“原始工序”“待处理”“标准化结果路线”三部分。左侧保留来源规程中的工序顺序，中间只列出需要判断的归并候选，右侧展示当前路线。
4. 对每个候选点击“确认合并”或“不合并”。可以使用“全部合并”“全部不合并”快速处理，但批量操作前要先检查候选名称和来源；系统建议保持独立的候选不应机械合并。
5. 需要调整名称时，点击“改名”，输入统一名称并点击“保存改名”。
6. 待处理候选清零后，右侧路线进入可编辑状态。选中工序后可以“上移”“下移”“并到上一工序”“并到下一工序”“增加”“拆开”“移除”“改名”，也可以拖拽调整顺序。展开“来源工序与工步”核对归并是否丢失原始内容。
7. 确认路线后点击底部“进入规则分析”。系统会先保存标准化母路线，保存完成才会进入第三步。

如果要从头重做第二步，点击页面右上角的重新处理入口并确认“重新推理第二步”。系统会保留上传文件和已提取的明细，但会作废已导入的分组模板，清除第二步路线、第三步问答、第四步映射、第五步规则包和第六步生成结果。完成路线与规则分析后，需要重新导入模板并完成映射。

### 5.3 第三步：规则分析

1. 左侧列表按工序展示状态和样本覆盖。使用“搜索工序名称”定位工序，再用“待确认”“确认中”“已确认”“全部”筛选。
2. 选中一段工序后，右侧先看文档覆盖、明细数量、来源节点和工序阶段，再处理“问题树补充判断”。
3. 问题树会给出单选或多选候选，通常带有“系统推荐”。先核对推荐项，再按当前样本选择；识别不到材料时可以点击“新增一行材料”手动填写材料牌号或材料大类。需要补充背景时，在备注框填写说明。
4. 每道工序可以使用“重新判断这道工序”清空当前判断后重答，也可以用“重新回答全部”清空第三步全部问答。重新回答全部会保留第二步路线和上传资料，但会作废已导入的分组模板及第四步映射；请重新导入模板、完成映射，并重新确认、发布规则包和生成路线。
5. 展开“差异样本”，比较出现和不出现该工序的文档；展开“内容证据摘录”和“原始工序明细”核对来源。点击样本文档可以打开预览；PDF 会按页显示，其他文件显示提取后的文本，也可以点击“打开原文件”。
6. 顶部“一键采纳全部推荐”适合先处理推荐明确的项目，仍需抽查已采纳的答案。完成后点击底部“进入模板分组映射”。

规则分析的目标是形成可解释的判断依据，不是让系统替审核人员自动决定工艺。样本覆盖不足、来源冲突或证据为空时，应回到原文或补充资料确认。

### 5.4 第四步：模板映射

1. 如果项目还没有模板，点击“导入模板”，选择 Kmsoft <code>.xml</code> 分组模板。系统先解析文件并显示分组数、特征选择数和校验问题。
2. 只有显示“校验通过”时，点击“确认并应用模板”进入映射工作区；如果显示“不可确认”，先更换文件或修复 XML 结构。更换已有模板时先阅读“更换影响评估”，确认旧映射会如何处理。
3. 左侧“工序与工步”中点击一个工步，右侧“模板分组”中搜索或展开分组，勾选适用的叶子特征，然后点击“关联”。已关联内容会显示在工步卡片上，可点击解除关联。
4. 只映射依赖零件特征、需要按特征判断适用性的工步；页面标记“无需特征映射”的工步应由所属工序规则处理，不要为了覆盖率强行关联。
5. 加工工序必须在左侧设置“精度”（粗加工、半精加工或精加工）。可点击“智能判定精度”，由当前配置的大模型结合完整路线、工序和工步补全未填写项；模型建议旁有标记，悬停可查看依据，也可手动修改。已有选择不会被覆盖，证据不足时保留“待确认”。辅助工序固定为“辅助工序”，无需填写加工精度。
6. “智能推荐”会为全部工步补充推荐，并继续补全缺失的加工精度；选中若干特征后点击“推荐”只针对当前选择。推荐失败时，当前人工映射会保留，可以稍后重试或继续手工关联。
7. 点击“保存工步映射”前，系统检查所有加工工序的精度。漏填时会列出具体工序、标红选择框并定位第一项，补齐后才能保存。没有未覆盖分组且存在有效关联时，按钮会变为“进入规则定稿”；仍有缺失时，页面会列出未关联的分组，先补齐再继续。

### 5.5 第五步：规则定稿

1. 页面顶部显示路线版本、规则包版本和“已确认/总数”。先处理带“待确认”的规则卡片；可以“一键全选”，再点击“确认选中规则”，也可以逐条处理。
2. 点击工序卡片右上角“规则修改”，选择出现方式：“始终出现（主工序）”表示每次纳入路线；“人工选择”表示在第六步显示可命名的是／否问题；“条件判断”表示根据字段条件或关联工序决定是否出现。工序与关联对象来自当前任务，适用于任意工序；镀铜／除铜只是示例，不是系统固定的处理对象。
3. 在“条件判断”中点击“＋ 添加条件”，选择字段、比较关系和取值。添加多项后，使用“条件满足方式”选择“全部满足”或“满足其一”；新组合默认全部满足。每项条件都可以删除，已有嵌套组合会保留。数字条件不能为空，只有顺序约束、没有出现条件或触发工序的配置不能保存。
4. 点击“＋ 添加工序关联”选择当前工序与其他工序的关系，多条关系可以组合。字段条件组的结果必须同时满足所有“跟随并排在其后”关系；“满足其一”只影响所在字段条件组，不会跳过关联要求。关系定义见下表。形成循环依赖或选择自身时，系统拒绝保存并保留原规则。
5. 点击“保存并确认”后配置才生效；“取消修改”放弃本次编辑。切换出现方式只是本地草稿，保存失败时保留编辑内容供修改重试。需要改写文字时，可在编辑区使用“修改原始描述”→“保存并识别”，识别后重新核对并确认；“恢复默认”和“重新识别”为辅助入口。
6. 页面右上角“重新识别”会重做第五步的普通规则识别，但保留用户填写的条件原文、人工主工序、人工 Bool 规则和模板映射；当前规则包和第六步结果会失效，需要重新发布和生成。
7. 点击“发布规则包”后，系统会在保存前自动执行发布预检。预检不通过时会显示阻断项，可点击“修复映射”“查看待处理规则”或“返回规则审核”逐项处理，修复后重新点击发布。预检通过时不会额外停留在预检弹窗，系统会直接保存并发布规则包。
8. 发布成功后记下规则包版本。页面会显示已发布版本并下载一个 ZIP，内含 <code>factor_table.json</code>、<code>full_route_table.json</code> 和 <code>rule_table.json</code> 三个快照文件。只有“已发布”版本会被第六步加载，草稿、未确认候选和预检失败的内容不会进入正式生成。

| 关联关系 | 实际含义 |
| --- | --- |
| 满足条件时自动跟随 | 关联工序达到触发条件，且当前工序的字段条件也满足时，自动纳入当前工序并排在关联工序后。添加多行时各行都需要满足；历史“任一生成”的关联组保留原含义。 |
| 仅调整先后顺序 | 两道工序都已纳入时，当前工序排在关联工序后；这条关系不会自动纳入任何工序。 |
| 关联工序是前置要求 | 当前工序要纳入路线时，关联工序也必须纳入且排在前面。系统会尝试补上前置工序；若它自身的条件不满足或被人工选择为“否”，系统会提示依赖未满足。 |
| 不能同时安排 | 两道工序不能同时纳入路线；如果规则或选择导致两者同时纳入，系统会提示冲突，不会替用户擅自删除其中一道。 |

例如“预处理”设置为人工选择，“表面精整”设置为“处理类别为 A 或要求精整”，再关联“满足条件时自动跟随预处理”：只有选择需要预处理，且两个字段条件至少满足一个，才安排表面精整。将条件组切换为“全部满足”，则两个字段条件都必须成立。工序名、字段和取值应替换为当前任务的实际内容。

**CAD 特征类别与真实几何：** 当前没有经过审定的自动分类器把“孔、外圆柱面”等几何名称转换成“普通孔/辅助孔、槽类特征”等规则类别。新导出的因素表会把 <code>cad.features</code> 作为可见多选输入，来源为 <code>manual_defaults.cad.features</code>；请由用户或已审定的上游分类器填写。工步候选仍绑定真实 CAD 几何，显式 <code>feature_type</code> 仍读取 CAD 特征名，两者分别填写。枚举使用导出 options 中的规范原值。旧包保持历史快照，需重新发布才使用新编译方式。

**三表导出边界：** 发布时同时校验下游 Demo 能否准确执行。互斥报错、部分前置依赖、开放文本比较、数值容差比较等无法等价表达的规则会阻断发布并提示原因。取反条件引用非必填因素，或对非必填因素使用“不等于”，也会被阻断：缺少输入时下游含义不同，需审定为必填或改写为明确的正向条件。非必填多选的“全部包含”至少选择一个值；系统不会静默改变规则含义。

**映射更新后再发布：** 调整最终工艺树的工序顺序，或增删、合并来源工步后，请返回模板映射核对并保存。发布预检会拒绝过期顺序，以及仍带有已移除或已变化来源候选的映射；仅重新确认规则不能替代更新映射。

### 5.6 第六步：验证生成

1. 进入“验证生成”后，页面会先加载当前任务最新的已发布规则包。如果提示没有可用规则包，点击“返回第5步”或“返回规则定稿”完成发布。
2. 在左侧“输入条件”填写规则包定义的字段。字段可能是文本、数字、单选、多选或“是/否”；带“必填”的字段必须补全。允许自定义时，在“自定义输入”中输入值后点击“+ 添加”。
3. 第一次试用可以点击“填入示例”，观察字段类型和输出结构；正式验证前用图样、订单或项目实际条件替换示例值。点击“清空”可移除当前输入。
4. 补全带“必填”的字段并确认“生成工艺路线”按钮可用后再点击。可选字段不需要为了凑满数量而填写；生成期间保持页面打开，右侧会显示“正在组合工序与工步”。
5. 结果区“工序工步树”显示工序数量、主线/条件工序数量和工步数量。点击每道工序的“工步”区域展开或收起下级工步，条件工序会单独标记。
6. 点击“复制 JSON”把完整结果复制到剪贴板，点击“导出 JSON”下载结果文件。导出的 JSON 适合交给下游系统或留档，不替代工艺卡、签审文件或现场验证。
7. 如果页面提示“规则包已更新”，说明已有更新后的已发布版本；确认输入条件后直接再次点击“生成工艺路线”即可刷新结果。只有规则仍在草稿、未确认或尚未发布时，才需要回到第五步完成发布。

如果全部工序均为固定安排、规则包没有输入字段，页面会提示“无需填写参数”，可以直接点击“生成工艺路线”。这类规则包的 <code>factor_table.json</code> 为合法空数组，不需要为了发布而编造因素。

第六步按填写的因素推演路线，不接收零件 CAD 几何。下游 CAD 引擎使用三个导出文件和实际零件数据，将模板候选特征落实到工步；无匹配候选的加工工步可能被省略，可选加工工序在没有剩余工步时也会省略，其跟随工序相应不再触发。验证时应分别核对因素规则和真实零件的分组／特征匹配结果。

## 6. 使用工艺知识库

左侧提供“知识问答”“工艺知识”“工艺资源”三个入口。默认打开知识问答；切换入口会保留本页已输入的问题及目录筛选。

- **工艺知识**：直接浏览工艺说明、典型路线和加工能力参考，可按分类、主题、关键词筛选及名称排序。
- **工艺资源**：切换设备、刀具、量具，查看关键参数。相同业务参数的资源合并展示，参数不同的记录分别保留，并保留来源。手册参考不代表企业实机台账或已验证适配。
- **列表与详情**：每页20项，显示匹配总数；点击条目打开右侧只读详情，查看完整参数、适用条件、原文和来源位置。待核对、冲突、异常范围会保留提示；“已核对原文”不等于业务批准。浏览无需模型，不提供新增、编辑或删除。

第一版目录复用已整理的本地资料，新上传规程不会自动进入目录。以下为知识问答操作：

1. 点击顶部“工艺知识库”。输入问题后点击“查询”，或者直接点击“试试这样问”中的示例问题。页面也可以选择检索条数。
2. 当前最小包的知识库基于内置轴套类样例，覆盖工艺说明、典型路线、历史工艺、加工能力、设备、刀具和量具等记录。常用问题包括“某材料衬套的历史工艺路线”“内孔精加工可以使用什么刀具和量具”“某车床的加工范围和精度参数”。
3. 阅读“知识库回答”后，向下展开证据卡片查看记录内容、典型步骤、能力指标、关联对象和来源文件。页面会区分“典型路线指导”和“历史工艺路线”：前者是参考方法，后者是原始执行记录。
4. 如果结果显示关系不足、没有找到相关知识或来源定位不可用，换用更具体的材料、工序、尺寸或资源名称查询。不要把没有明确证据的关系当成系统结论。
5. 在带有“采纳为依据”的证据卡片上，确认记录确实适用于当前项目、路线和工序后再点击。采纳动作只会保存一条知识依据记录并在本页显示，不会自动回填第三步或改写已发布规则包。需要使用这条依据时，请人工回到第三步对照内容，在问题树或备注中补充并重新确认规则；当前最小运行包没有在第三步装载“企业知识依据”面板。

## 7. 重跑、版本和数据管理

### 7.1 什么时候需要重跑

- 新增或删除主资料后：回到第二步重新提炼和归并。
- 修改标准路线后：第三步需要重新读取并回答受影响的工序。
- 重新回答第三步全部问题后：重新导入分组模板、完成第四步映射，再确认并发布第五步规则。
- 修改或重新识别第五步规则后：旧规则包和第六步结果会标记过期，必须重新发布并生成。
- 更换模板后：检查模板映射和发布预检，不要直接使用旧映射。

页面弹出的“继续保留 / 重新处理”清单是失效范围的依据；确认前先阅读清单。

### 7.2 运行数据位置

空白交付包默认使用以下本地目录：

~~~text
data/db/process_mind.db
data/uploads/
data/config/process_settings.json
~~~

Docker 默认把上述目录映射到宿主机 <code>./data</code>。如果升级的是旧版包，并且 API 根目录已经存在 <code>process_mind.db</code>、<code>uploads/</code> 或 <code>process_settings.json</code>，后端会优先读取这些旧路径以保持兼容；迁移或备份时要检查旧路径和 <code>data/</code> 两处，确认实际正在使用的目录。也可以通过 <code>PROCESSMIND_DATA_DIR</code>、<code>PROCESSMIND_DB_PATH</code>、<code>PROCESSMIND_UPLOAD_DIR</code> 和 <code>PROCESSMIND_SETTINGS_PATH</code> 显式指定位置。Win7 交付包默认使用 <code>%LOCALAPPDATA%\ProcessMind</code>。SQLite 默认使用 WAL 日志，复制数据库文件前先停止 API，或使用一致性备份工具，不能在服务运行时只复制主数据库文件。备份时至少同时保存数据库、上传文件和设置文件；设置文件可能包含已保存的模型凭据，应按机密数据保护。恢复后要确认路径和权限一致。

## 8. 常见问题

| 现象 | 常见原因 | 处理方式 |
| --- | --- | --- |
| 页面显示“先新建工艺规程任务” | 没有当前任务 | 点击“新建任务”，创建后再上传主资料。 |
| “进入路线归并”不可点击 | 当前任务没有主资料，或文件仍在上传 | 等待上传完成，确认文件出现在主资料列表。 |
| 第二步显示“分析出错” | API/模型不可用、文件解析失败或响应超时 | 先看错误面板；检查“模型设置”并“测试连接”，确认文件格式后点击“重试”。 |
| 第二步一直有待处理候选 | 还有归并建议未判断 | 在“待处理”面板逐项点击“确认合并”或“不合并”，必要时先改名。 |
| 第三步提示没有可分析的已保存路线 | 第二步只看了预览，没有保存标准路线 | 返回路线归并，完成候选处理并点击“进入规则分析”。 |
| 第四步没有可用模板 | 尚未导入 Kmsoft XML | 点击“导入模板”，先通过预览校验再应用。 |
| 模板显示“不可确认” | XML 结构存在阻断性问题 | 阅读“校验问题清单”，修复或更换 XML 后重新解析。 |
| 第五步发布预检被阻断 | 还有规则未确认、条件不完整或映射缺失 | 打开预检明细，按“查看待处理规则”“修复映射”等按钮逐项处理。 |
| 第六步提示没有规则包 | 当前任务没有已发布版本 | 返回规则定稿，完成确认和发布；草稿不会被第六步使用。 |
| 生成按钮仍不可用 | 必填输入字段未补全，或字段值需要修正 | 查看“已填写 x/y”和字段状态；可以先“填入示例”确认表单行为。 |
| 结果提示规则包已更新 | 已有更新后的已发布规则包，当前结果仍是旧版本 | 确认输入条件后直接点击“生成工艺路线”刷新；只有规则尚未发布时才回到第五步。 |
| 知识库没有结果 | 问题超出内置样例或检索词太宽 | 使用材料、工序、尺寸、设备或量具名称缩小问题，查看示例问题。 |
| 启动时报端口占用 | 8000、5173 或 8080 被其他进程使用 | 停止占用进程，或为本地/Docker 设置新的端口；不要结束无关服务。 |
| Win7 启动提示 DLL 或运行时错误 | 缺少 KB2533623、运行时不完整或包被手工改动 | 按 Win7 交付说明安装补丁并重启，使用完整交付 ZIP，不要复制单个 DLL 代替补丁。 |

## 9. 安全与审核要求

- 生产资料和模型密钥不要放在源码仓库、截图、日志或共享压缩包中。
- 交付包只应包含明确允许的源码、运行时和示例配置，不要直接压缩开发目录；开发目录可能包含数据库、上传文档和密钥。
- 上传文件和生成结果可能含有图样、材料和工艺信息，按组织的信息分级要求保存和传输。
- AI 识别、路线归并、知识库回答和规则建议都需要领域人员核对；来源不足、样本覆盖不足或标准有效性无法确认时，应保留人工结论和复核记录。
- 规则包发布后要记录版本号；发现规则或模板变化时，回到对应步骤重跑并重新发布，不要只在结果文件上手工改名。
