# ProcessMind 用户使用说明

本文面向工艺工程师、规则审核人员和负责本地部署的技术人员，按当前最小可运行包的页面和启动脚本编写。系统没有账号体系，默认只监听本机地址；需要在内网共享时，请在外层增加访问控制和网关。

## 1. 先了解几个概念

| 概念 | 含义 |
| --- | --- |
| 任务 | 一组独立的工艺规程资料、路线分析结果和规则版本。系统按任务保存工作流状态。 |
| 主资料 | 用于提炼典型路线的工艺规程文件，当前仅支持可提取有效文字、表格的 PDF。 |
| 标准化母路线 | 从多份规程中归并出的统一工序顺序，是后续规则分析的基础。 |
| 规则分析 | 针对每道工序确认它在什么材料、结构、精度或要求下出现。 |
| 模板映射 | 把需要按零件特征判断的工步关联到 Kmsoft XML 分组模板。 |
| 可验证规则与规则包 | 第四步保存当前路线和已确认规则，供第五步验证；验证后可导出规则包，按需在第六步补充模板映射。 |
| 工艺路线验证 | 输入一个零件的实际条件，让第四步保存的当前可验证规则输出工序和工步。 |

建议先按“1 上传资料 → 2 路线归并 → 3 规则分析 → 4 规则定稿 → 5 工艺路线验证 → 6 模板映射（可选）”走完一个小样本，再扩大到完整资料集。不需要模板映射时，可在第五步验证满意后直接导出规则包。

## 2. 准备环境并启动

### 2.1 本地开发运行

本地运行建议准备 Python 3.11+、Node.js 20+ 和 npm 10+。首次运行在项目目录执行：

~~~bash
./bootstrap.sh
~~~

脚本会创建后端虚拟环境并安装依赖，再安装前端依赖。随后开两个终端：

终端一启动后端：

~~~bash
./start-api.sh
~~~

终端二启动前端：

~~~bash
./start-ui.sh
~~~

默认地址：

- Web：<http://127.0.0.1:5173>
- API：<http://127.0.0.1:8000>
- API 文档：<http://127.0.0.1:8000/docs>

若端口已占用，可在启动前设置 <code>PROCESSMIND_API_PORT</code> 或 <code>PROCESSMIND_UI_PORT</code>；前端代理会跟随 API 端口。启动脚本只绑定 <code>127.0.0.1</code>，关闭终端会停止对应进程。

### 2.2 Docker 运行

在项目目录执行：

~~~bash
cp .env.compose.example .env
docker compose up -d --build
~~~

默认 Web 地址为 <http://127.0.0.1:8080>，停止服务：

~~~bash
docker compose down
~~~

Web 端口可以通过 <code>.env</code> 中的 <code>PROCESSMIND_WEB_PORT</code> 调整。Docker 将宿主机 <code>./data</code> 挂载到容器的 <code>/runtime-data</code>，因此数据库和上传文件会保留在项目的 <code>data/</code> 目录。

### 2.3 Windows 普通交付包

双击 <code>start-windows.cmd</code> 启动，双击 <code>stop-windows.cmd</code> 停止。首次启动会检查运行时和前端依赖，按窗口提示完成初始化。具体包是否包含便携运行时，以交付包内文件为准。

### 2.4 Windows 7 SP1 离线包

Win7 包使用独立的 Python 3.8.10 运行时，目标机不需要安装 Python 或 Node.js。目标机需要：

1. 预装 Chrome 109 或 Edge 109。
2. 以管理员身份运行 <code>prerequisites\install-kb2533623.bat</code>，安装完成后重启。
3. 解压交付 ZIP 后双击 <code>start-win7.bat</code>。

启动器会优先使用已安装的 Firefox（火狐）。如果火狐安装在自定义目录，在 CMD 执行 <code>set "PROCESSMIND_BROWSER=D:\Mozilla Firefox\firefox.exe"</code>（替换为实际路径），再运行 <code>start-win7.bat</code>。找不到火狐时仍可使用原有浏览器；Firefox 页面兼容性需在 Win7 目标机上验证。

辅助命令：

~~~text
status-win7.cmd    查看 API 健康状态
stop-win7.cmd      停止当前包启动的 API
~~~

三个命令执行后均保留窗口，便于查看报错；按任意键只关闭命令窗口。API 在后台运行，启动完成后没有单独的 API 控制台窗口。自动化调用前执行 <code>set "PROCESSMIND_NO_PAUSE=1"</code>，再使用 <code>call start-win7.bat --no-browser</code>、<code>call status-win7.cmd</code>、<code>call stop-win7.cmd</code>。

状态命令只有服务健康且归属当前目录时返回 0，否则返回 1。关闭命令成功停止或确认已退出时返回 0；无法确认归属、权限不足或关闭失败时返回 1 并保留可重试的状态。不要用 <code>taskkill /IM python.exe</code> 关闭系统。自定义端口启动传入 <code>--port 18087</code>；状态和关闭默认读取状态文件里的端口，状态丢失时可显式传入同一端口。不同解压版本共用默认运行目录时，请先从原目录关闭，再启动新包。

启停和状态命令对同一运行目录互斥；提示“另一个命令正在执行”时请等待前一个命令结束后重试。无法读取匹配当前目录的进程命令行时，启动器保留状态并返回失败，不会仅凭端口或健康接口认定进程归属。

Win7 包默认把数据库、上传文件、日志、缓存和 PID 写入 <code>%LOCALAPPDATA%\ProcessMind</code>，可用同名环境变量 <code>PROCESSMIND_RUNTIME_DIR</code> 指向其他可写目录。关闭浏览器不会停止 API，需要执行 <code>stop-win7.cmd</code> 完全退出。

## 3. 第一次配置模型

1. 打开 Web 页面，点击顶部的“模型设置”。
2. 填写“API 基础路径”。它应是模型服务的 OpenAI 兼容接口地址，例如 <code>https://api.deepseek.com/v1</code>；不要把本项目的 <code>/api</code> 地址填在这里。
3. 填写“API Key”。已保存的密钥会被隐藏；更新时输入新值，保持原值时留空，必要时可点击“清空已保存密钥”。
4. 填写“默认模型”。首次配置或刚更换服务地址时直接手动输入模型名；刷新图标读取的是已保存配置对应的模型列表，建议先测试并保存，再按需刷新。
5. 点击“测试连接”，确认服务能返回，再点击“保存设置”。

模型配置用于路线提炼、智能推荐、规则识别和知识库回答。模型服务不可用时，页面会显示具体错误；不要把真实密钥写入 Git、压缩包或截图。部署环境也可以通过 <code>.env</code> 或环境变量注入 <code>LLM_API_URL</code>、<code>LLM_API_KEY</code>、<code>LLM_MODEL</code>。

## 4. 新建任务并准备资料

### 4.1 新建或选择任务

1. 进入“上传资料”。
2. 点击“新建任务”，填写任务名称，例如 <code>42CrMo 主轴加工</code>，点击“确认创建”。
3. 在任务卡片中点击任务名称切换当前任务。顶部工作流和后续页面都会使用当前任务。
4. 删除任务时先点击任务卡片上的删除按钮，再在确认框中点击“确认删除”。删除会同时清理该任务的文档和提炼结果，无法恢复；正式删除前请先备份实际运行中的数据库、上传目录和设置文件。

### 4.2 上传主资料

在“典型工艺规程文件”卡片中点击或拖拽文件。工艺规程上传仅支持 <code>.pdf</code>，文件应包含可提取的有效文字、表格。Word、Excel 等来源请先导出为保留文字的 PDF；不要仅修改文件扩展名。

当前不自动识别纯图片扫描件。扫描件请先在外部完成文字识别，再核对正文和工序工步是否能提取。损坏、受密码保护、没有有效文字或存在疑似无法读取正文的页面时，系统会指出文件及相关页码；按提示解除密码、完成文字识别或重新导出后再上传。

可以一次选择多份 PDF，也可以点击“继续添加文件”补充。当前后端默认限制为单次最多 20 个文件、单文件 50 MB、单批次 200 MB；超过限制时按提示分批上传。

上传完成后，文件会出现在列表中。误传文件可以点击文件右侧的删除按钮；如果还没有主资料，底部“进入路线归并”按钮会保持禁用。

### 4.3 补充要求与参考资料边界

当前不提供项目辅助参考资料的上传、在线编写或管理入口，原参考资料接口也已移除。需要补充工艺要求时，请在后续问答、备注或规则修改中按实际依据填写。工艺知识库的查询和证据浏览仍是独立功能，见第 6 节。

仅工艺规程主资料限制为 PDF；第六步导入的 Kmsoft 分组模板仍为 XML，路线结果和规则包仍使用各自的 JSON、ZIP 下载格式。

## 5. 六步业务流程

### 5.1 第一步：上传资料

完成任务选择和主资料上传后，确认文件数量、文件名和 PDF 内容无误，点击底部“进入路线归并”。系统只会把当前任务的主资料带入后续提炼。

### 5.2 第二步：路线归并

1. 进入页面后点击“开始 AI 智能提炼”。系统会显示提炼阶段和进度；处理时间取决于文件数量、页数和模型响应。
2. 如果出现“分析出错”，先阅读错误面板和校验信息，再点击“重试”。确认 API、模型和资料内容可用后再重试，不要连续重复提交。
3. 提炼完成后，页面分为“原始工序”“待处理”“标准化结果路线”三部分。左侧保留来源规程中的工序顺序，中间只列出需要判断的归并候选，右侧展示当前路线。
4. 对每个候选点击“确认合并”或“不合并”。可以使用“全部合并”“全部不合并”快速处理，但批量操作前要先检查候选名称和来源；系统建议保持独立的候选不应机械合并。
5. 需要调整名称时，点击“改名”，输入统一名称并点击“保存改名”。
6. 待处理候选清零后，右侧路线进入可编辑状态。选中工序后可以“上移”“下移”“并到上一工序”“并到下一工序”“增加”“拆开”“移除”“改名”，也可以拖拽调整顺序。展开“来源工序与工步”核对归并是否丢失原始内容。
7. 确认路线后点击底部“进入规则分析”。系统会先保存标准化母路线，保存完成才会进入第三步。

如果要从头重做第二步，点击页面右上角的重新处理入口并确认“重新推理第二步”。系统会保留上传文件和已提取的明细，清除第二步路线、第三步问答、第四步规则定稿与可验证规则、第五步验证结果，并作废已导入模板和第六步映射。重新完成规则定稿与路线验证后，需要模板映射时再导入模板。

### 5.3 第三步：规则分析

1. 左侧列表按工序展示状态和样本覆盖。使用“搜索工序名称”定位工序，再用状态筛选查看待处理或已完成的项目。
2. 选中工序后，按右侧当前问题作答。问题和候选随工序及当前任务而定；核对“系统推荐”及其依据，再选择实际适用的选项。多选问题需要确认选值；阈值、材料等信息按该题显示的候选或输入框填写。
3. 材料题按当前题目区分牌号和类别。出现材料表格时，可以勾选样本行；需要补充且页面提供“新增一行材料”时，填写牌号或从已有材料大类中选择。新增的是当前题目的材料行，类别仍从已有选项选择。备注框用于补充判断依据。
4. 顶部“一键采纳全部推荐”与手动回答使用同一套问题、候选和规则转换；仍需抽查已采纳答案。推荐不完整或不可用的工序保留待处理状态，可手动回答或按提示“重试推荐”；问答生成失败时使用“重新生成问答”。已开始回答的工序保留原问答版本和答案。
5. 通过样本文档入口核对原工艺要求。点击样本文档可按页预览 PDF，也可点击“打开原文件”。当前工序需要重答时使用问题面板的重新作答入口；全量重做使用顶部“重新回答全部”，影响范围见第 7.1 节。
6. 全部必答问题完成后，点击底部“进入规则定稿”进入第四步。进入第四步后，第三步仅供查看；后续规则调整在第四步进行。需要重新开展第三步问答时，使用“重新回答全部”并确认其清理范围。

规则分析的目标是形成可解释的判断依据。样本覆盖不足、来源冲突或证据为空时，应回到原文确认，再补充答案或人工审核。

### 5.4 第四步：规则定稿

1. 先核对每道工序的规则与来源。可以逐条“确认规则”，或使用顶栏“确认全部规则”。全路线确认覆盖筛选外、未勾选和未展开的待确认项；内容未变且有效的已确认规则保留。
2. 全路线确认会跳过未保存草稿、缺少内容或有效候选的工序，并逐项列出工序及原因；普通请求失败不撤销此前成功。未保存编辑会保留，不会自动保存或覆盖。若服务端明确提示工作流版本过期，本次队列会停止，后续项显示未执行原因；先复制备份当前草稿，再按提示取消修改、刷新并核对最新路线。
3. 操作期间请等待完成，页面会防止重复确认及同时进入验证。完成后显示实际已确认数、剩余待处理数，仍停留第四步。根据逐项原因保存或取消草稿、补充内容后，再确认剩余项。
4. 点击“规则修改”，每道工序选择一种出现方式，含义见下表。切换方式和编辑条件属于本地草稿，点击“保存并确认”才生效；取消则放弃本次编辑，保存失败保留编辑内容供修正重试。
5. “条件工序”默认展示当前工序常用字段，可展开“本项目全部条件”。点击“＋ 添加条件”，依次选择字段、判断关系和候选值；各行条件全部满足才生成工序，特征与方位应属于同一加工对象。候选以当前项目清单为准，不能用推荐子集代替全部合法候选；数值条件需要填写有效数值。
6. 日常调整统一通过“规则修改”完成。识别失败时按异常提示使用“重试识别”，恢复后重新核对条件并确认。规则内容变化后，需要重新保存并使用新规则生成路线。
7. 处理完未保存、忙碌及待确认项后，点击“保存并进入路线验证”。系统会校验并保存当前可验证规则，通过后进入第五步。第四步的确认操作与这个入口分别执行；无需先做模板映射，也不会在确认全部后自动跳转或下载规则包。

| 出现方式 | 使用方法与含义 |
| --- | --- |
| 主工序 | 每次生成路线都纳入当前工序。 |
| Bool 工序 | 填写“验证时显示”的名称；第五步用勾选决定是否生成，默认不勾选。 |
| 条件工序 | 按当前工序的字段、判断关系及候选值设置出现条件。 |
| 关联工序 | 在“跟随工序”中选择来源工序；来源纳入路线时自动生成当前工序，并排在其后，允许中间穿插其他工序及逐级带出。 |

例如，钻孔规则可要求“加工特征包含任一孔（盲孔）、孔（通孔）”且“同一对象方位等于周边”。这两个条件共同决定是否生成钻孔；具体特征、方位和阈值应按当前任务实际要求选择，不把示例值代填为新零件条件。

### 5.5 第五步：工艺路线验证

1. 页面加载第四步保存的当前可验证规则，顶部显示规则版本。若提示没有可用规则，点击“返回规则定稿”，先完成第四步保存；不需要先下载或发布规则包才能验证。
2. 左侧按“基本信息（材料）”“加工因素（特征、方位、精度）”“人工安排（Bool勾选）”组织实际输入；仅显示当前规则需要的项目，并按加工对象展示相关因素。材料牌号只能从当前候选中单选，不提供自由新增。缺少材料候选时，返回第四步核对材料规则并保存，再重新进入验证。
3. 本项目实际尺寸精度通过下拉单选 IT5、IT6、IT7、IT8、IT9、IT10，包含两端。允许输入不等于满足触发条件：例如规则为“IT7及更高精度”，IT6和IT8都可选，但IT6满足、IT8不满足。此范围用于第五步实际值，不自动缩改第三、四步规则阈值。
4. 补全带“必填”的字段；人工安排工序默认不勾选，勾选才生成。其他字段按显示的类型和候选填写，仅在该字段明确允许时使用自定义输入。“填入示例”用于了解表单和结果，正式验证前应换成图样、订单或项目实际值；“清空”可移除输入。
5. 点击“生成工艺路线”，等待右侧完成推演。在“工序工步树”中核对工序、条件工序标记和各工步，可以展开或收起工步。
6. 工步默认收起，点击各工序旁的“工步”按钮按需展开。当前规则没有输入字段时，无需填写参数，可以直接生成固定路线。
7. 使用当前规则成功生成并检查路线后，可点击右上角“导出规则包”；不需要模板映射的用户可在此结束。需要模板映射时，点击底部“继续分组模板映射（可选）”。两个入口均要求当前规则版本已有有效生成结果，旧版本结果不能直接用于导出或进入映射。
8. 第四步规则变化后，旧验证结果失效，需要保存当前规则并重新生成；出现“规则已更新”时，应核对版本与输入，再生成当前结果。第五步修改实际参数后，旧路线清除且暂时不能导出；需按当前参数重新生成，迟到的旧请求结果不会覆盖当前输入。

**下载格式：** “导出规则包”下载 <code>任务名_规则包_V版本号.zip</code>，内含 <code>factor_table.json</code>（因素及输入定义）、<code>full_route_table.json</code>（全集工序工步）、<code>rule_table.json</code>（规则）。三份文件采用约定的精简数组格式，对外编号保持稳定，来源证据与审核历史留在软件内部。这些文件与当前已验证规则版本一致；未做第六步时不附加模板映射。下载不替代工艺卡、签审文件或现场验证。

**CAD 边界：** 第五步按实际因素推演路线，不接收零件 CAD 几何。材料、特征类别、方位和精度应依据实际零件填写；规则包中的模板候选特征与真实几何匹配，仍需在下游系统核对。不要把一次示例路线视为所有零件均已验证。

已下载的旧包保留当时的快照，不会随页面或规则修改自动升级；下游使用时请核对对应版本和文件结构。

### 5.6 第六步：模板映射（可选）

1. 先在第五步使用当前规则生成并检查路线，再进入本页。映射对象是已验证规则对应的完整母路线（含可能分支），不是只映射本次参数生成的单条路线。
2. 点击“导入模板”，选择 Kmsoft <code>.xml</code> 分组模板。核对分组、特征和校验问题，只有校验通过才能确认应用。更换已有模板前阅读影响评估；更换会清除旧模板的叶子豁免，需重新核对。
3. 在左侧“工序与工步”选中工步，在右侧模板树中搜索或展开分组，勾选适用特征后点击“关联”。已关联内容显示在工步上，可解除关联。加工工步按特征映射输出；辅助工步按所属工序规则保留，不需要为了覆盖率强行关联。
4. 每个工步都可“删除”，包括已映射和未映射项。删除会从本次映射清单和映射导出中移除该工步，并解除它原有的特征关联；不改写已验证的规则核心和完整母路线，也不会自动豁免空出的叶子分组。
5. 点击“恢复全部工步”可恢复本次删除项，恢复项统一为未映射，不恢复旧关联；其他未删除工步的映射保留。若删除后调整了其他工步的顺序，恢复时保留这些工步已调整的相对顺序。
6. 使用工步旁“上移”“下移”调整同一道工序内的可见工步，首末位置相应禁用。移动时关联跟随原工步；不跨工序移动，也不调整工序本身的顺序。保存和映射导出使用调整后的工步顺序。
7. 右侧叶子分组所在行显示“待映射”“已映射”或“已豁免”。确实无需映射的待映射叶子可点“豁免映射”，该节点置灰且不再标为待映射；“取消豁免”仍可点击，取消后恢复待映射。已映射叶子的豁免按钮禁用；父分组不提供批量豁免。
8. 为每道加工工序选择精度（粗加工、半精加工或精加工）；辅助工序显示“辅助工序”。“智能推荐”可补充工步关联及缺失精度，已选特征旁的“推荐”针对当前选择。模型建议需人工核对，失败时保留人工映射和操作；漏填加工精度会在保存时提示具体工序。
9. 核对剩余待映射叶子与需输出的工步后，点击“保存并导出规则包”；已保存且满足条件时按钮显示“更新规则包”。一次操作保存当前映射、删除、排序、豁免和精度，并下载包含本次映射结果的 ZIP，三份文件名与第五步相同，<code>full_route_table.json</code> 使用本次映射交付的工步内容与顺序。保存校验失败时按具体提示修正，不把未保存草稿当作已导出结果。
10. 若提示“映射和规则包已保存，下载未完成”，使用“重新下载规则包”下载同一已保存版本。离开页面前先保存或“放弃未保存的修改”，推荐或保存进行中请等待完成。

## 6. 使用工艺知识库

左侧提供“知识问答”“工艺知识”“工艺资源”三个入口。默认打开知识问答；切换入口会保留本页已输入的问题及目录筛选。

- **工艺知识**：直接浏览工艺说明、典型路线和加工能力参考，可按分类、主题、关键词筛选及名称排序。
- **工艺资源**：切换设备、刀具、量具，查看关键参数。相同业务参数的资源合并展示，参数不同的记录分别保留，并保留来源。手册参考不代表企业实机台账或已验证适配。
- **列表与详情**：每页20项，显示匹配总数；点击条目打开右侧只读详情，查看完整参数、适用条件、原文和来源位置。待核对、冲突、异常范围会保留提示；“已核对原文”不等于业务批准。浏览无需模型，不提供新增、编辑或删除。

第一版目录复用已整理的本地资料，新上传规程不会自动进入目录。以下为知识问答操作：

1. 点击顶部“工艺知识库”。输入问题后点击“查询”，或者直接点击“试试这样问”中的示例问题。页面也可以选择检索条数。
2. 当前最小包的知识库基于内置轴套类样例，覆盖工艺说明、典型路线、历史工艺、加工能力、设备、刀具和量具等记录。常用问题包括“某材料衬套的历史工艺路线”“内孔精加工可以使用什么刀具和量具”“某车床的加工范围和精度参数”。
3. 阅读“知识库回答”后，向下展开证据卡片查看记录内容、典型步骤、能力指标、关联对象和来源文件。页面会区分“典型路线指导”和“历史工艺路线”：前者是参考方法，后者是原始执行记录。
4. 如果结果显示关系不足、没有找到相关知识或来源定位不可用，换用更具体的材料、工序、尺寸或资源名称查询。不要把没有明确证据的关系当成系统结论。
5. 在带有“采纳为依据”的证据卡片上，确认记录确实适用于当前项目、路线和工序后再点击。采纳动作只会保存一条知识依据记录并在本页显示，不会自动回填第三步或改写已发布规则包。需要使用这条依据时，请人工回到第三步对照内容，在问题树或备注中补充并重新确认规则；当前最小运行包没有在第三步装载“企业知识依据”面板。

## 7. 重跑、版本和数据管理

### 7.1 什么时候需要重跑

- 新增或删除主资料后：回到第二步重新提炼和归并；重新推理会清除第二步及后续结果，保留上传文件和已提取明细。
- 修改标准路线后：第三步重新读取并核对受影响工序，再完成第四步定稿和第五步验证。
- “重新回答全部”后：保留第二步路线和上传资料，清除第三步答案、第四步规则及可验证版本、第五步结果，并作废已导入模板和第六步映射。重新完成第三至五步；需要映射时，再在第六步导入模板并映射。
- 进入第四步后：第三步只读。局部规则调整在第四步完成；确需重做问答时使用“重新回答全部”。
- 修改或重新识别第四步规则后：重新确认并保存当前可验证规则，到第五步重新生成和检查；旧验证结果不能用于当前导出。全路线确认保留草稿和有效已确认规则，不能替代“保存并进入路线验证”。
- 更换模板后：阅读影响评估，重新核对可保留及失效的映射；旧叶子豁免清除。工步删除、恢复、排序、豁免或精度变化后，在第六步保存并导出更新包；这些映射操作不改写已验证的规则核心与完整母路线。

页面弹出的“继续保留 / 重新处理”清单是失效范围的依据；确认前先阅读清单。使用旧下载包的下游系统不会自动取得新规则或映射，需要交付相应新版本。

### 7.2 运行数据位置

空白交付包默认使用以下本地目录：

~~~text
data/db/process_mind.db
data/uploads/
data/config/process_settings.json
~~~

Docker 默认把上述目录映射到宿主机 <code>./data</code>。如果升级的是旧版包，并且 API 根目录已经存在 <code>process_mind.db</code>、<code>uploads/</code> 或 <code>process_settings.json</code>，后端会优先读取这些旧路径以保持兼容；迁移或备份时要检查旧路径和 <code>data/</code> 两处，确认实际正在使用的目录。也可以通过 <code>PROCESSMIND_DATA_DIR</code>、<code>PROCESSMIND_DB_PATH</code>、<code>PROCESSMIND_UPLOAD_DIR</code> 和 <code>PROCESSMIND_SETTINGS_PATH</code> 显式指定位置。Win7 交付包默认使用 <code>%LOCALAPPDATA%\ProcessMind</code>。SQLite 默认使用 WAL 日志，复制数据库文件前先停止 API，或使用一致性备份工具，不能在服务运行时只复制主数据库文件。备份时至少同时保存数据库、上传文件和设置文件；设置文件可能包含已保存的模型凭据，应按机密数据保护。恢复后要确认路径和权限一致。

## 8. 常见问题

| 现象 | 常见原因 | 处理方式 |
| --- | --- | --- |
| 页面显示“先新建工艺规程任务” | 没有当前任务 | 点击“新建任务”，创建后再上传主资料。 |
| Office 或 JSON 工艺规程不能上传 | 主资料仅接受 PDF | 将来源导出为可提取文字的 PDF；规则包 JSON 和分组模板 XML 使用各自的后续入口。 |
| PDF 提示扫描页、正文不足、损坏或加密 | 无法提取有效正文或读取受限 | 按文件和页码提示先做文字识别、解除密码或重新导出，再核对工序工步完整性。 |
| 找不到参考资料上传或在线编写 | 项目辅助参考资料功能已移除 | 在问答、备注或规则修改中补充有依据的要求；知识库仍可独立查询。 |
| “进入路线归并”不可点击 | 当前任务没有主资料，或文件仍在上传 | 等待上传完成，确认文件出现在主资料列表。 |
| 第二步显示“分析出错” | API/模型不可用、文件解析失败或响应超时 | 先看错误面板；检查“模型设置”并“测试连接”，确认文件内容后点击“重试”。 |
| 第二步一直有待处理候选 | 还有归并建议未判断 | 在“待处理”面板逐项点击“确认合并”或“不合并”，必要时先改名。 |
| 第三步提示没有可分析的已保存路线 | 第二步只看了预览，没有保存标准路线 | 返回路线归并，完成候选处理并点击“进入规则分析”。 |
| 第三步无法进入规则定稿 | 仍有必答问题、处理中工序或未完成的推荐路径 | 按状态筛选找到未完成工序；补全答案，推荐不可用时手动回答或重试。 |
| 第三步只能查看，不能修改答案 | 当前路线已进入第四步定稿 | 到第四步修改规则；需要全量重答时使用“重新回答全部”，先阅读清理范围。 |
| 确认全部后仍有剩余项，或没有进入第五步 | 草稿、缺内容、无效候选或失败项被保留；确认结束仍留在第四步 | 阅读逐项原因，保存或取消草稿并补齐规则，再点击“保存并进入路线验证”。 |
| 全路线确认提示版本过期，后续项未执行 | 上游工作流已变更，本地版本过期 | 保留或备份当前草稿后按提示核对最新路线；已成功项不因本次冲突回滚，不重复提交旧版本。 |
| 第五步没有可用规则或导出不可用 | 第四步尚未保存，或当前规则尚无有效生成结果 | 先完成第四步保存，再用当前实际参数生成并检查路线，之后导出或进入可选映射。 |
| 第五步无法自由添加材料牌号 | 材料使用当前规则的固定候选 | 返回第四步核对材料规则、补充候选并保存，再重新加载验证输入。 |
| IT8 可选，但未生成要求 IT7 及更高精度的工序 | 输入合法范围与工序触发条件不同 | IT5～IT10 均为本项目合法实际输入；按当前规则判断是否满足，使用真实值验证。 |
| 生成按钮仍不可用 | 必填输入未补全，或字段值需要修正 | 查看字段状态；可先“填入示例”了解表单，正式生成时换成实际值。 |
| 规则更新后看不到原结果，或旧结果标为过期 | 第四步规则变化使旧验证失效 | 保存当前规则，再在第五步重新生成；核对版本后重新导出。 |
| 第六步没有模板，或模板显示“不可确认” | 未导入 XML，或 XML 存在阻断性问题 | 导入 Kmsoft XML，阅读校验清单，修复或更换后确认应用。 |
| 删除后恢复的工步没有旧关联 | 恢复项统一为未映射 | 重新关联所需特征；其他工步已调整的顺序和有效映射仍保留。 |
| 叶子分组的豁免按钮不可用 | 该叶子已映射，或当前操作尚在进行 | 先核对现有关联；只有待映射叶子可以直接豁免，已豁免叶子可取消豁免。 |
| 第六步不能保存，或保存后下载未完成 | 加工精度未填、映射校验失败或下载失败 | 先处理具体工序/分组提示；已保存但下载失败时点“重新下载规则包”。 |
| 知识库没有结果 | 问题超出内置样例或检索词太宽 | 使用材料、工序、尺寸、设备或量具名称缩小问题，查看示例问题。 |
| 启动时报端口占用 | 8000、5173 或 8080 被其他进程使用 | 停止占用进程，或为本地/Docker 设置新的端口；不要结束无关服务。 |
| Win7 启动提示 DLL 或运行时错误 | 缺少 KB2533623、运行时不完整或包被手工改动 | 按 Win7 交付说明安装补丁并重启，使用完整交付 ZIP，不要复制单个 DLL 代替补丁。 |

## 9. 安全与审核要求

- 生产资料和模型密钥不要放在源码仓库、截图、日志或共享压缩包中。
- 交付包只应包含明确允许的源码、运行时和示例配置，不要直接压缩开发目录；开发目录可能包含数据库、上传文档和密钥。
- 上传文件和生成结果可能含有图样、材料和工艺信息，按组织的信息分级要求保存和传输。
- AI 识别、路线归并、知识库回答和规则建议都需要领域人员核对；来源不足、样本覆盖不足或标准有效性无法确认时，应保留人工结论和复核记录。
- 导出规则包后要记录版本号；发现规则或模板变化时，回到对应步骤核对，按当前规则重新验证并导出，不要只在结果文件上手工改名。
