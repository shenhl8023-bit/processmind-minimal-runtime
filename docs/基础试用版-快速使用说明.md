# ProcessMind 基础试用版 · 快速使用说明

适用：Windows 7 SP1 64 位、内网环境。
有效期：2026 年 12 月 30 日全天可用；北京时间 2026 年 12 月 31 日 00:00 起停止使用。
本版暂不开放“工艺知识库”页面；顶部入口已隐藏，不影响五步流程和三表导出。

## 一、第一次打开

1. 将整个 ZIP 解压到本机目录，例如 D:\ProcessMindBasicTrial。请先解压，不要在压缩包内直接运行，也不要只拷贝启动文件。
2. 使用 Chrome 109 或 Edge 109。电脑没有这类浏览器时，请联系内网管理员安装。
3. 首次在 Win7 上使用，按需以管理员身份运行 prerequisites\install-kb2533623.bat，按提示完成安装并重启。已有该补丁时按提示跳过即可。
4. 双击 start-win7.bat。页面通常会自动打开；未打开时，用上述浏览器访问启动窗口显示的地址，默认是 http://127.0.0.1:8000。修改端口后，以窗口显示的地址为准。
5. 点击页面顶部“模型设置”，填写管理员提供的内网模型 API 地址、API Key 和模型名，点击“测试连接”，成功后“保存设置”。地址必须是当前电脑能访问的内网模型服务；本包不附带模型。

软件已包含 Python 运行时，无需安装 Python、Node.js，也不需要联网激活。默认通过本机浏览器使用。

### 修改端口和更新版本

端口默认是 8000。提示被其他软件占用时，用记事本打开软件根目录的 launcher-config.json，只改 port 后面的数字，例如：

```json
{
  "port": 8001
}
```

保存后双击 start-win7.bat，软件会自动打开 http://127.0.0.1:8001。也可改用其他未占用的端口，数字范围为 1～65535；不要删除括号、引号或冒号，不要在数字外添加引号，也不要新增其他配置项。

· 已经运行时修改配置：先双击 stop-win7.cmd，再双击 start-win7.bat，新端口才会生效。直接再次双击启动，会打开当前仍在运行的页面，并提示如何应用新配置。
· 停止和查看状态：仍双击 stop-win7.cmd、status-win7.cmd 即可，它们按实际运行端口操作，无需手动填写端口。只修改端口不会清空任务、上传资料或模型设置。
· 换版本或换解压目录：先在旧包目录运行 stop-win7.cmd，确认停止后再启动新包。新包发现旧后台仍在运行时，会显示旧包关闭脚本的完整路径；按提示关闭旧后台后重试。同一个数据目录只能运行一份后台。
· 新包默认仍为 8000。之前改过端口时，将新包 launcher-config.json 中的数字改成需要的端口，再启动即可。

## 二、最快导出三表：按顶部五步走

建议先选同一类零件的 2～5 份有代表性的工艺规程走通流程，核对结果后再增加资料。文件质量、模型响应和人工核对会影响处理时间。

第 1 步“上传资料”
  点击“新建任务”，输入名称并确认。仅上传包含可识别文字的 PDF 工艺规程。
  Word、Excel 等资料请先导出为保留文字的 PDF。上传后点击“进入路线归并”。

第 2 步“路线归并”
  点击“开始 AI 智能提炼”，等待完成。
  处理待确认的合并建议，核对工序名称、先后顺序和工步，完成后点击“进入规则分析”。

第 3 步“规则分析”
  按工序核对问题与推荐答案，补充材料、适用条件等。
  可以先点“一键采纳全部推荐”处理推荐项，再逐项抽查、修正。完成后点击“进入规则定稿”。

第 4 步“规则定稿”
  核对每道工序的规则，日常调整点击“规则修改”。
  · 主工序：每次生成路线都纳入。
  · Bool 工序：由第五步复选框决定是否安排，默认不勾选。
  · 条件工序：按材料、特征、方位或精度等条件判断。
  · 关联工序：跟随指定工序纳入，并按规则安排顺序。
  可以逐项“确认规则”或“确认全部规则”；需要修改的先“保存并确认”。
  待处理项完成后点击“保存并进入路线验证”，第四步不下载规则包。

第 5 步“工艺路线验证”——在这里导出三表
  输入已知零件的实际条件，点击“生成工艺路线”，与原规程对照。
  建议核对有代表性的普通及特殊要求零件，满意后点击右上角“导出规则包”。
  浏览器下载“任务名称_规则包_V版本号.zip”。基础版无需XML模板或分组映射。
  修改参数后需重新生成；修改规则后需回第四步保存，再用新规则重新生成。

## 三、下载后取哪些文件

打开浏览器的“下载内容”，找到刚下载的 ZIP 并解压。ZIP 内只有以下三份 JSON 数据文件：

factor_table.json       因素表：因素定义、字段类型、选项、单位、输入校验和必填要求。
full_route_table.json   全集路线表：全部工序、工步、稳定编号、先后顺序和必要约束。
rule_table.json         规则表：工序出现规则、工序关联及人工选择配置。

三表采用约定的精简数组格式，对外短编号及关联引用同步转换；分析资料、来源证据和审核历史保留在软件内部。全集路线表覆盖完整母路线，和本次参数生成的单条路线不同；未映射时不附加模板绑定。

已有下载不会自动更新。修改规则后，重新保存、验证并导出；同一对象重复导出时保持短编号稳定。
建议将同一次导出的三表 ZIP 一起保存，避免混用不同版本的文件。对接其他软件前请先确认对方读取的数据格式。

最快操作顺序：新建任务并上传 → 提炼归并 → 核对规则分析 → 保存并进入验证 → 生成并检查路线 → 导出并解压三表。

## 四、日常关闭、备份和常见问题

· 关闭浏览器不会停止后台；完全退出请双击同目录的 stop-win7.cmd。查看服务状态可双击 status-win7.cmd。
· 数据默认保存在 %LOCALAPPDATA%\ProcessMindBasicTrial。备份前先关闭软件，再复制整个目录；请同时保存导出的三表 ZIP。管理员设置了自定义运行目录时，以管理员配置为准。
· 页面打不开：先运行 status-win7.cmd，再尝试重新运行 start-win7.bat，查看窗口报错。其他软件占用端口时按上文修改 launcher-config.json；旧版后台未退出时，先从提示的旧包目录关闭服务。若配置格式错误，恢复为 {"port": 8000} 后重试。
· 模型连接失败：核对内网地址、模型名、Key 和内网连通性；不要改填公网模型地址。
· 文件提取失败：检查文件是否清晰、可读且包含工序工步；旧格式先另存，扫描件应先准备可识别文本。
· 点击导出未下载：先用当前规则和参数成功生成路线，检查浏览器下载记录和下载权限，再重新导出。
· 修改了资料、路线或规则：重新确认、保存并验证，使用新导出的三表；不要混用不同版本。
· 显示“试用已到期”：本版本已停止业务使用，请联系供应方。本地数据不会自动删除。
